### 학습 목표 : 교착 상태 회피 방법에 대한 이해

### 학습 내용 요약 :

- 교착 상태 회피를 하기 위해서는 시스템의 상태를 계속 감시해야 한다.
- 감시하면서 만약 프로세스가 자원을 요청했을 때 자원을 할당했다고 가정 시 안전한 시퀀스가 있다면 해당 프로세스에 자원을 할당해준다.
    - 만약 안전한 시퀀스를 찾지 못하면 자원 요청을 거부한다. ⇒ 낮은 자원 이용률이라는 단점이 생김
    - 안전한 시퀀스란 모든 프로세스가 정상 종류 가능한 상태가 되는 프로세스 진행 순서가 존재하는 것이다.
- Dijkstra의 은행원 알고리즘 (한 가지 종류의 자원을 가정) ⇒ Habermann’s 알고리즘 (여러 종류의 자원을 가정)
    - 가정 : 프로세스, 자원 수가 고정, 최대 필요 자원 수를 알고 있다
    - 가정이 비현실적이다.

### DeadLock Avoidance

- 시스템의 상태를 계속 감시
- 시스템이 데드락 상태가 될 가능성이 있는 자원 할당 요청 보류
- 시스템 상태를 항상 `safe state` 로 유지

safe state

- 모든 프로세스가 정상 종료가 가능한 상태
- safe sequence 가 존재
    - 데드락 상태가 되지 않을 수 있음을 보장한다.

unsafe state

- DeadLock 상태가 될 가능성이 있는 상태
- 반드시 발생한다는 것은 아님

### Dijkstra Banker’s Algorithm

- DeadLock Avoidance 를 위한 간단한 이론적 기법
- 가정
    - 한 종류의 자원이 여러 개
- 시스템을 항상 safe state로 유지

예시

- 리소스 타입 1개, 10개의 리소스 유닛, 3개의 프로세스 존재
    - 프로세스1은 2개가 더 필요하고, 2는 4개, 3은 3개가 더 필요할 때 현재 가용한 자원이 2개라면
    - 프로세스1에게 2개를 주어서 자원을 다 쓰면 3개를 반납하고, 이 3개를 프로세스3에게 주어서 자원을 다 쓰면 5개를 반납하고 남은 자원을 프로세스 2에게 주면 모든 프로세스가 정상 종료가 가능하다!
        - 카드 돌려막기 비슷한 느낌이다.
    - P1 → P3 → P2 (safe sequence) ⇒ 하나 이상이면 안전 상태임

![image.png](/assets/images/lec7_dijlkstra_bankers.png)

- P2 에게 하나를 빌려준다고 가정했을 때 safe sequence가 존재하지 않으면 요청을 거절한다.

### Habermann’s Algorithm

- dijstra의 확장
- 여러 종류의 자원을 가정
- 시스템을 항상 safe state 로 유지
- 자원의 종류만 늘어났지 사실상 다잌스트라의 은행원 알고리즘과 동일함.
    - 현재 상태에서 특정 프로세스에게 자원을 할당하여 반납 받고 이런 안전한 시퀀스가 존재하면 해당 프로세스에 자원을 빌려주고
    - 만약, 자원을 빌려주는 가정을 했는데 안전한 시퀀스를 못찾으면 빌려주지 않는다.

### DeadLock Avoidance

- High Overload
    - 시스템을 항상 감시하고 있어야 한다.
- Low Resource Utilization
    - Safe state 유지를 위해, 사용되지 않는 자원이 존재
- Not practical
    - 가정 : 프로세스 수, 자원이 고정, 필요한 최대 자원 수를 알고 있다
    - 현실적이지 않은 가정임
