### 학습 내용 요약

- RAM은 휘발성 기억 장치로, DRAM, SRAM, SDRAM, DDR SDRAM으로 구분할 수 있다.
- 논리주소는 CPU와 실행 프로그램이 알고 있는 데이터의 주소로 한 프로그램에서 0번지부터 최대 한계 레지스터 번호까지 사용할 수 있다.
    - 베이스 레지스터는 한 프로그램의 시작번지의 메모리 주소번지 값을 저장한다.
- 논리 주소를 물리 주소로 변환하는 방법을 MMU(Memory Management Unit)이라고 하며, CPU와 실행 프로그램의 논리 주소에 베이스 레지스터 값을 더하여 메모리의 물리 주소로 변환한다.
- 캐시 메모리는 CPU안의 레지스터와 메모리 사이에 존재하는 SRAM 계열의 메모리로, CPU가 사용할 법한 데이터를 참조 지역성의 원리에 따라 저장하여, CPU가 빠르게 데이터를 송수신(접근)할 수 있도록 한다.

## RAM의 특징과 종류

### RAM의 특징

- 휘발성 저장 장치 (volatile memory)
- CPU는 보조기억장치에 직접 접근하지 못하기 때문에, 보조기억장치인 비휘발성 저장 장치에는 ‘보관할 대상’을 저장하고, 휘발성 저장 장치인 RAM에는 ‘실행할 대상’을 저장한다.
- CPU가 실행하고 싶은 프로그램이 보조기억장치에 있다면 이를 RAM으로 복사하여 저장한 뒤 실행함.

### RAM의 용량과 성능

- 만약 RAM의 용량이 실행하고 싶은 프로그램 A, B, C 중 하나만 저장할 수 있을 만큼 작다면 CPU가 프로그램 A를 실행하고 싶을 때는 보조기억장치에서 A를 RAM으로 가져오고, 프로그램 B를 사용하고 싶을 때는 RAM으로 B를 가져오는 식으로 해야됨. ⇒ RAM의 용량이 충분하다면 세 개 다 데이터를 미리 가져와서 RAM에 저장하여 구동시킬 수 있음. ⇒ RAM의 용량이 크면 많은 프로그램들을 동시에 빠르게 실행하는 데 유리함.
- 하지만, 용량이 무한정 크다고 해서 프로그램 실행 속도가 빨라지는 것은 아님. 용량이 크면 많은 프로그램들을 RAM에 저장하여 빠르게 실행시킬 수는 있지만, 필요 이상으로 커졌을 때 속도가 그에 비례하여 증가하지는 않음. ~ 책을 100권 이상 올려놓을 수 있는 책상에서 책을 읽든, 1000권 올려놓을 수 있는 책상에서 책을 읽든, 책장을 오가는 시간에는 별 차이가 없음.

### RAM의 종류

- 크게 DRAM, SRAM, SDRAM, DDR SDRAM이 있음

***DRAM***

- Dynamic RAM의 준말. → 데이터가 동적으로 변하는 (사라지는) RAM을 의미함.
- 즉, 시간이 지나면 저장된 데이터가 점차 사라지는 RAM ⇒ 데이터의 소멸을 막기 위해 일정 주기로 데이터를 재활성화(다시 저장) 해야 함.
- 우리가 일반적으로 메모리로써 사용하는 RAM은 DRAM. 소비 전력이 비교적 낮고, 저렴하고, 집적도가 높기 때문에 대용량으로 설계하기가 용이함.
    - 집적도 : **같은 면적의 칩에 얼마나 많은 정보를 저장할 수 있는지**를 나타내는 지표
    - DRAM 셀은 데이터를 **커패시터(축전기)에 전하를 저장**하는 방식으로 기록
    - **하나의 비트(1bit)를 저장**하는 데 **1개의 트랜지스터와 1개의 커패시터**만 필요함. 이처럼 구성 요소가 단순하기 때문에 같은 면적에 더 많은 셀을 만들 수 있어 **집적도가 높다.**

***SRAM***

- Static RAM의 준말 → 저장된 데이터가 변하지 않는 RAM (전원이 공급되지 않으면 저장된 내용이 날아감)
- 주기적으로 데이터를 재활성화할 필요도 없고, DRAM보다 일반적으로 속도도 더 빠름
- DRAM보다 집적도가 낮고, 소비 전력도 크며, 가격도 더 비쌈. ⇒ 대용량으로 만들어질 필요는 없지만 속도가 빨라야 하는 저장 장치, 가령 ‘캐시 메모리’에서 사용됨.
    - SRAM 셀은 **플립플롭(Flip-Flop) 회로**를 사용하며, 데이터를 **전압의 형태로 계속 유지한다**.
    - **하나의 비트(1bit)를 저장**하는 데 최소 **4개에서 6개의 트랜지스터**가 필요함. DRAM 셀보다 훨씬 복잡한 구조이기 때문에 같은 면적에 더 적은 셀만 만들 수 있어 **집적도가 낮다.**

***SDRAM***

- Synchronous Dynamic RAM은 클럭 신호와 동기화된, 발전된 형태의 DRAM
- 클럭 신호와 동기화되었다는 말은 클럭 타이밍에 맞춰 CPU와 정보를 주고받을 수 있음을 의미함. ⇒ 클럭에 맞춰 동작하며 클럭마다 CPU와 정보를 주고받을 수 있는 DRAM

***DDR SDRAM***

- Double Data Rate SDRAM은 최근 가장 흔히 사용되는 RAM.
- DDR SDRAM은 대역폭을 넓혀 속도를 빠르게 만든 SDRAM.
    - 대역폭이란(data rate) ‘데이터를 주고받는 길의 너비’를 의미함.
- 한 클럭에 하나씩 정보를 주고받을 수 있는 SDRAM과 비교했을 때 DDR SDRAM은 너비가 두 배인 도로와 같음. 즉, 한 클럭에 한 번씩 CPU와 데이터를 주고받을 수 있는 SDRAM에 비해 DDR SDRAM은 두 배의 대역폭으로 한 클럭당 두 번씩 CPU와 데이터를 주고받을 수 있음.
    - 한 클럭당 하나씩 데이터를 주고받을 수 있는 SDRAM을 SDR SDRAM이라고 부리기도 함.
- DDR2 SDRAM은 DDR SDRAM보다 대역폭이 두 배 넓은 SDRAM. 다시 말해 DDR2 SDRAM은 SDR SDRAM보다 너비가 4 배 넓은 도로와도 같음.
- DDR3 SDRAM은 DDR SDRAM보다 대역폭이 두 배 넓고, SDR SDRAM보다 대역폭이 8 배 넓음.
    - DDR4 SDRAM은 SDR SDRAM보다 16배 넓은 대역폭을 가진다.
    - 실제 시장에 나온 제품의 최대 성능을 기준으로 하면 16배 이상임 ~ 24배까지도
    - DDR5 SDRAM도 마찬가지로 이론적으로는 32배 이지만, 실제는 36배까지도 차이가 남.

## 메모리의 주소 공간

> 주소는 두 종류가 있음. 물리 주소와 논리 주소. 
물리 주소는 메모리 하드웨어가 사용하는 주소이고, 
논리 주소는 CPU와 실행 중인 프로그램이 사용하는 주소임.
> 

### 물리 주소와 논리 주소

> Q. CPU와 실행 중인 프로그램은 현재 메모리 몇 번지에 무엇이 저장되어 있는지 다 알고 있을까요?
A. 다 알지 못함. 그 이유는 메모리에 저장된 정보는 시시각각 변하기 때문. 메모리에는 새롭게 실행되는 프로그램이 시시때때로 적재되고, 실행이 끝난 프로그램은 삭제됨. 게다가 같은 프로그램을 실행하더라도 실행할 때마다 적재되는 주소가 달라질 수 있음.
> 
- 메모리가 사용하는 물리 주소(physical address)는 말 그대로 정보가 실제로 저장된 하드웨어상의 주소를 의미함.
- 반면, CPU와 실행 중인 프로그램이 사용하는 논리 주소(logical address)는 실행 중인 프로그램 각각에게 부여된 0번지부터 시작되는 주소를 의미함.
    - 메모장, 게임, 인터넷 브라우저는 모두 물리 주소가 아닌 0번지부터 시작하는 자신만을 위한 주소인 논리 주소를 가지고 있음.
    - ‘10번지’라는 주소는 메모장에도, 게임에도, 인터넷 브라우저에도 논리 주소로써 존재할 수 있음.
- CPU가 이해하는 주소가 논리 주소라고는 해도 CPU가 메모리와 상호작용하려면 논리 주소와 물리 주소 간의 변환이 이루어져야 함. 변환이 없다면 CPU와 메모리는 서로 이해할 수 없는 주소 체계를 가지고 각자 다른 이야기만 할 뿐 결코 상호작용할 수 없음
- 논리 주소와 물리 주소 간의 변환은 CPU와 주소 버스 사이에 위치한 **메모리 관리 장치(MMU : Memory Management Unit)라는 하드웨어에 의해 수행됨.**
- MMU는 CPU가 발생시킨 논리 주소에 베이스 레지스터 값을 더하여 논리 주소를 물리 주소로 변환함.
    - 예를 들어, 현재 베이스 레지스터에 1500이 저장되어 있고, CPU가 발생시킨 논리 주소가 100번지라면 이 논리 주소는 물리주소 15100번지로 변환됨.
- **베이스 레지스터**는 프로그램의 가장 작은 물리 주소, 즉 **프로그램의 첫 물리 주소를 저장하는 셈**이고  논리 주소는 프로그램의 시작점으로부터 떨어진 거리인 셈

### 메모리 보호 기법

> 메모장 프로그램의 물리 주소가 1000번지 ~ 1999번지, 인터넷 브라우저의 물리 주소가 2000번지 ~ 2999번지, 게임 프로그램의 물리 주소가 3000번지 ~ 3999번지라고 가정하자
만약 메모장 프로그램 명령어 중 (논리 주소) 1500번지에 숫자 100을 저장하라 와 같은 명령어가 있다면 숫자 100은 어떤 물리 주소에 저장될까? 이 명령어는 실행되어도 안전할까?
> 
- 위와 같은 명령어들은 실행되어서는 안됨. 논리 주소 범위를 벗어나는 명령어 실행을 방지하고 실행 중인 프로그램이 다른 프로그램에 영향을 받지 않도록 보호할 방법이 필요함. 이를 **한계 레지스터**라는 레지스터가 담당.
- 베이스 레지스터가 실행 중인 프로그램의 가장 작은 물리 주소를 저장한다면, **한계 레지스터는 논리 주소의 최대 크기를 저장함**. ⇒ 즉 프로그램의 물리 주소 범위는 베이스 레지스터 값 이상, 베이스 레지스터 값 + 한계 레지스터 값 미만이 됨.
- CPU는 메모리에 접근하기 전에 접근하고자 하는 논리 주소가 한계 레지스터보다 작은지를 항상 검사함. 만약 CPU가 한계 레지스터보다 높은 논리 주소에 접근하려고 하면 인터럽트(트랩)를 발생시켜 실행을 중단함.

## 캐시 메모리

> CPU가 메모리에 접근하는 시간은 CPU의 연산 속도보다 느립니다. CPU가 연산을 빨리 한다고 해도 메모리에 접근하는 시간이 느리면 CPU의 빠른 연산 속도는 아무런 쓸모가 없다. 이를 위한 저장 장치가 바로 **캐시 메모리**
캐시 메모리의 탄생 배경과 특징을 이해하기 위해서 우선 저장 **장치 계층 구조**라는 개념을 이해해야 한다.
> 

### 저장 장치 계층 구조

- 저장 장치는 일반적으로 아래와 같은 명제를 따른다.
    1. CPU와 가까운 저장 장치는 빠르고, 멀리 있는 저장 장치는 느리다
    2. 속도가 빠른 저장 장치는 저장 용량이 적고, 가격이 비싸다.
- 컴퓨터가 사용하는 저장 장치들은 ‘CPU에 얼마나 가까운가’를 기준으로 계층적으로 나타낼 수 있고, 이를 저장 장치 계층 구조 (memory hierarchy)라고 한다.
    - 레지스터 → 메모리 → 보조기억장치

### 캐시 메모리

- 캐시 메모리(cache memory)는 CPU와 메모리 사이에 위치하고, 레지스터보다 용량이 크고 메모리보다 빠른 SRAM 기반의 저장 장치
- CPU의 연산 속도와 메모리 접근 속도의 차이를 조금이나마 줄이기 위해 탄생함.
    - CPU를 집으로, 메모리에 접근하는 행위를 물건을 사러 가는 것으로 비유하자면, ‘메모리는 물건은 많지만 집과는 멀리 떨어져 있어 왕복이 오래 걸리는 대형 마트’이고, ‘캐시 메모리는 물건이 많지는 않아도 집과 가까이 있는 편의점’과 같다
    - 레지스터 → 캐시 메모리 → 메모리 → 보조기억장치
- 컴퓨터 내부에는 여러 개의 캐시 메모리가 있고, CPU와 가까운 순서대로 계층을 구성함.
    - 코어와 가장 가까운 캐시 메모리를 L1 캐시, 그 다음 L2 캐시, 그 다음 L3 캐시

### 참조 지역성 원리

- 캐시 메모리는 CPU가 사용할 법한 대상을 예측하여 저장한다. 이때 자주 사용할 것으로 예측한 데이터가 실제로 들어맞아 캐시 메모리 내 데이터가 CPU에 활용될 경우를 캐시 히트(cache hit)라고 한다.
    - 반대로 자주 사용될 것으로 예측하여 캐시 메모리에 저장했지만, 예측이 틀려 메모리에서 필요한 데이터를 직접 가져와야 하는 경우를 캐시 미스(cache miss)라고 함.
    - 캐시가 히트되는 비율을 캐시 적중률 (cache hit ratio)
- 우리가 사용하는 컴퓨터의 캐시 적중률은 대략 85 ~ 95% 이상임.
- 캐시 메모리는 한 가지 원칙에 따라 메모리로부터 가져올 데이터를 결정함. 바로 참조 지역성 원리(locality of reference, principle of locality)
    1. CPU는 최근에 접근했던 메모리 공간에 다시 접근하려는 경향이 있다.
    2. CPU는 접근한 메모리 공간 근처를 접근하려는 경향이 있다.

시간 지역성 (temporal locality)

- 최근에 접근했던 메모리 공간에 다시 접근하려는 경향 ~ 같은 변수를 여러 번 사용

공간 지역성 (spatial locality)

- CPU가 워드 프로세서 프로그램을 실행할 적에는 워드 프로세서 프로그램이 모여 있는 공간 근처를 집중적으로 접근할 것이고, 사용자가 입력을 할 적에는 입력 기능이 모여 있는 공간 근처를 집중적으로 접근함.
- 이렇게 메모리 공간근처를 접근하려는 경향을 공간 지역성이라고 함.
