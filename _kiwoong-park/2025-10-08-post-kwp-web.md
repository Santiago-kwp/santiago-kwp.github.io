### 학습 내용 

- Q: 웹서버란 무엇인가?
    
    A: 내가 작성한 HTML 문서를 어떻게 지구 반대편에 있는 사람에게 즉시 보여줄 수 있을까? 라는 문제를 해결하기 위해 등장한 것이 웹 서버. 특정 컴퓨터에 저장되어 있는 index.html 파일을 보여줘라는 요청이 오면 해당 파일을 그대로 보내주는 역할만 수행함. 모든 사람이 접속해도 항상 똑같은 페이지만 보이는 정적 웹페이지 호스팅의 역할을 함. 
    
    정적 웹 (static web) : 모든 사람이 항상 똑같은 페이지만 본다. 대표적으로 nginx, Apache, MS의 IIS, Caddy
    
- Q: WAS (Web Application Server) 란 무엇인가?
    
    A : 웹이 대중화되면서 사람들이 더 많은 것을 요구함 ⇒ 동적인 웹 페이지를 생성하기 위해 WAS가 등장함. ⇒ 동적인 웹 페이지란? 새로운 HTML을 실시간으로 만들어 내는 것 ⇒ 특정 요청을 받으면 미리 약속된 프로그램을 실행 시키고, 그 결과물을 사용자에게 제공한다.
    
    사람들의 요구
    
    - 홈페이지에 방문자 수를 표시하고 싶어
    - 사용자마다 다른 정보를 보여주고 싶어
    - 사람들이 글을 남길 수 있는 방명록을 만들고 싶어 등
    
    요청에 따라 코드를 실행하는 엔진 : WAS의 원형
    
    - 서버가 단순히 파일 전달에서 생각하고, 연산하고, 로직을 처리하기 시작한 순간
    
    동적인 요청이 들어왔을 때, 백엔드 프레임워크 코드를 실행하고 그 결과를 웹 서버에게 돌려주는 백엔드의 심장부
    
- Q : 백엔드 프레임워크와 WAS의 차이점은?
    
    A: 백엔드 프레임워크는 자동차를 만들기 위한 정교한 설계도와 부품 세트
    
    - 개발자가 회원가입, 결제 같은 비지니스 로직 개발 도움
    - 미리 준비된 뼈대와 도구 모음
    - Spring, Django, FastAPI, Express 등
    
    WAS는 자동차를 실제로 움직이게 만드는 엔진
    
    - 개발자가 백엔드 프레임워크를 이용해 작성한 코드가 실제 서버에서 실행시켜주는 환경 그 자체
    - 즉, WAS 없이는 백엔드 프레임워크는 동작할 수 없음.
    - 동적인 요청이 들어왔을 때, 백엔드 프레임워크 코드를 실행하고 그 결과를 웹 서버에게 돌려주는 백엔드의 심장부
    - Apache, Jetty, Gunicon, Uvicon, Nodejs 런타임, MS의 IIS

- Q : 데이터베이스는 왜 필요한가? 파일시스템만으로 쓰면 안되나?
    
    A : 회원들의 아이디, 비밀번호를 안전하게 관리해야하며, 쇼핑몰의 수백만개 재고를 관리해야하고, 여러명의 사용자가 동시에 마지막 남은 한정판 신발을 구매하려고 하려고 하는데, 딱 한 명만 살 수 있게 해줘야 함.
    ⇒ 즉, 영구적으로 데이터를 저장하고, 안전하게 관리하고, 동시접근을 제어해야 함
    
    파일 시스템의 치명적인 문제
    
    - 동시성 제어가 불가능함 ⇒ DB는 락과 같은 정교한 메커니즘으로 경합조건, 즉 race condition을 막고 데이터의 일관성을 지켜줌
        - 송금과 수취는 반드시 한 묶음으로 성공하거나, 실패해야 함. 하나라도 실패하면 모두 없던 일이 되어야 함.
        - 데이터베이스는 이런 작업을 트랜잭션으로 관리하여 데이터의 무결성을 유지함!
    - 검색속도가 처참함…
        - 파일시스템에서 특정회원을 찾으려면 컴퓨터는 파일의 첫줄부터 마지막 줄까지 모든 내용을 읽어서 비교해야함
        - 데이터베이스는 인덱스라는 기능을 통해서 데이터의 위치정보를 미리 정리해둬서 수억개의 데이터 속에서도 원하는 정보를 빠르게 검색할 수 있음.

- Q: 웹서버, WAS, 데이터베이스가 실제 서비스에서 어떻게 협력해?
    
    A : 
    
    1. 사용자가 특정 웹사이트에 접속 요청을 하게 되면 웹 서버가 가장 먼저 사용자의 요청을 받고, 프론트엔드 애플리케이션을 구동하는데 필요한 정적 파일 (HTML, CSS, JS)들을 사용자의 브라우저로 빠르게 전송 ⇒ 사용자의 브라우저는 수신한 정적 파일들로 화면을 그림(렌더링) ⇒ 사용자에게 홈페이지 화면이 보임
    
    ![image.png](/assets/images/clientToWebServer.png)
    
    1. 사용자가 아이디, 패스워드를 입력 후 로그인 버튼을 클릭하게 되면, /api 요청이므로 웹 서버가 처리하지 않고 WAS로 전달 ⇒ 비지니스 로직이 시작되어 데이터베이스로 보내 회원 정보를 조회하고, 일치하는 회원 여부 응답 ⇒ WAS에서 인증 토큰을 생성하고 ⇒ 이 토큰이 포함된 json 객체로 로그인 성공 응답을 웹 서버로 보냄 ⇒ 웹 서버는 사용자에게 최종 응답을 전달하며 브라우저는 로그인 성공 화면을 띄우고, 토큰을 브라우저에 저장함.
    
    ![image.png](/assets/images/clientPostToWebServerAndWASAndDB.png)
    
    1. 사용자가 특정 게시글을 클릭하면, GET 요청을 통해 인증 토큰을 포함한 요청이 웹 서버로 전달됨 ⇒ 웹 서버는 api 요청이므로 역시 WAS에 전달함. ⇒ WAS에서는 인증 토큰을 검사하여 사용자를 식별하며, 권한이 있는 경우 DB 에 해당 게시글을 조회하는 쿼리를 날림 ⇒ DB는 해당 게시글 데이터를 WAS에 전달하며 WAS에서는 웹서버에 보내기 위해 데이터를 JSON 형식으로 가공 ⇒ 웹서버로 게시글 json 데이터를 응답함 ⇒ 웹 서버는 사용자 브라우저에 최종 응답을 전달하고 ⇒ 브라우저에서 게시글 데이터를 수신 완료하면 해당 데이터로 화면에 제목과 본문을 렌더링함.
