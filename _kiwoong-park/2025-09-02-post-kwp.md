# [OS] Lecture5. Process Scheduling (3/5)

### 순 공부 시간

9.2.23:13 ~ 9.3.00:23 (70분)

### 학습 목표 : 스케쥴링 기본 알고리즘에 대한 이해

### 학습 내용 요약 :

- 스케쥴링 기법은 선점형과 비선점형 스케쥴링으로 구분할 수 있음. 선점형은 중간에 끼어들기가 가능한 것이고, 비선점형은 중간에 끼어들 수 없는 것임
- 비선점형 스케쥴링 알고리즘으로는 FCFS, SPN, HRRN 이 있고
- 선점형 스케쥴링 알고리즘으로는 Round robin, SRTN이 있음 → 선점형은 문맥 교환에 따른 오버헤드 발생
- 공평성에 방점을 둔 알고리즘은 FCFS, Round robin 알고리즘이라고 할 수 있고, 조금 더 시스템 성능 및 효율 향상을 위한 알고리즘은 SPN 계열 알고리즘(SPN, SRTN, HRRN) 이라고 할 수 있음.
- SPN 계열 알고리즘은 실행 시간 예측이 필요하다.

### 스케쥴링 기본 알고리즘

- FCFS (First Come First Serve)
    - 도착 시간 기준 (ready queue 기준) 먼저 도착한 프로세스부터 시작한다.
    - 비선점형 (Non-preemptive scheduling)
    - 자원을 효율적으로 사용 가능
    - 일괄처리 시스템에 적합 → 대화형 시스템에 부적합
    - convoy effect : 긴 수행 시간을 가진 프로세스에 의해서 다른 프로세스들이 긴 대기시간을 가지게 됨
    - 긴 평균 응답 시간

- Round Robin
    - Preemptive scheduling (선점형 스케쥴링)
    - 도착 시간 기준 먼저 도착한 프로세스부터 시작
    - 자원 사용 제한 시간 (time quantum) ⇒ 프로세스는 할당된 시간이 지나면 자원 반납
      ⇒ context switch 발생으로 오버헤드가 클 수 있음
    - 특정 프로세스의 독점 방지
    - 대화형, 시분할 시스템에 적합하다.
    - Time quantum이 성능에 주요 요인
        - 아주 크다면 사실상 fcfs와 같음
        - 아주 작다면 모든 프로세스가 사실상 각각의 프로세서 위에서 실행되는 것처럼 느낌
            - 하지만 아주 큰 문맥 교환 오버헤드 발생
    - 할당된 시간이 끝나면 레디 큐의 맨뒤에가서 다시 줄을 선다!

  ![image.png](/assets/images/lec5_roundRobin.png)


- SPN (Shortest Process Next)
    - Non Preemptive scheduling (비선점형 스케쥴링)
    - burst time 기준(수행 시간 기준) 짧은 프로세스를 먼저 처리
    - 평균 대기 시간 감소 ⇒ 시스템 내 프로세스 수 최소화 ⇒ 스케쥴링 부하 감소, 메모리 절약 ⇒ 시스템 효율 향상
    - 많은 프로세스들에게 빠른 응답 시간을 제공
    - Starvation (무한대기, 기아) 현상 발생 : 수행 시간이 긴 프로세스는 영원히 프로세서를 할당받지 못함
    - 정확한 수행 시간을 알 수 없음 ⇒ 실행 시간 예측 기법이 별도 필요
- SRTN (Shortest Remaining Time Next)
    - SPN의 변형
    - Preemptive scheduling (선점형)
        - 잔여 시간이 더 적은 프로세스가 ready 상태가 되면 먼저 선점됨
    - SPN의 장점 극대화
    - 프로세스 생성 시, 총 실행 시간 예측이 필요함
    - 잔여 실행을 계속 추적해야 함 = overhead
    - context switch 오버헤드 발생
    - 구현 및 사용이 비현실적임
- HRRN (High Response Ratio Next)
    - SPN + Aging concepts, Non Preemptive scheduling
    - 프로세스 대기 시간을 고려하여 기회를 제공 ⇒ Response ratio가 높은 프로세스를 우선함
    - Response Ratio = (대기 시간 + 실행 시간 ) / 실행 시간
    - SPN의 장점 + 기아 현상 방지
    - 실행 시간 예측 방법 필요

### 선점형 vs. 비선점형 ⏳

헷갈릴 수 있는 부분이 바로 이 **'선점'** 이라는 단어의 의미입니다. 운영체제 스케줄링에서 말하는 선점(preemption)은 다음과 같이 정의할 수 있다.

- **선점형(Preemptive)**: 한 프로세스가 CPU를 사용하고 있을 때, **더 높은 우선순위**를 가진 다른 프로세스가 나타나면 현재 실행 중인 프로세스를 **강제로 중단**시키고 CPU를 빼앗아 올 수 있는 방식이다. 예를 들어, 라운드 로빈(Round Robin) 스케줄링은 할당된 시간(time slice)이 끝나면 현재 프로세스를 강제로 중단시키고 다음 프로세스로 넘어갑니다.
- **비선점형(Non-preemptive)**: 한 프로세스가 CPU를 할당받으면, 그 프로세스가 **스스로 CPU를 반납**하거나(예: 입출력 작업을 기다릴 때) 또는 **작업을 완전히 마칠 때까지** 다른 프로세스가 CPU를 빼앗을 수 없는 방식입니다. FCFS가 바로 여기에 해당됩니다. 먼저 온 프로세스가 작업이 끝날 때까지 CPU를 독점하기 때문에, 다른 프로세스가 중간에 끼어들 수 없습니다.
