## [OS] Lecture5. Process Scheduling (5/5)

### 순 공부 시간

9.6.토 00:16 ~ 00:50 (34분)

### 학습 목표 : MLQ, MFQ 개념에 대한 이해

### 학습 내용 요약 :

- MLQ, MFQ는 둘 다 하나의 레디 큐를 쓰는 것이 아니라 여러 개의 레디 큐를 사용하여 프로세스 스케쥴링을 하는 방식
- MLQ는 각각의 큐별로 스케쥴링 기법이 존재하며, 각 큐에 할당된 프로세스는 다른 레디 큐로 이동할 수 없다.
  - 우선순위가 높은 프로세스들은 우선순위가 높은 큐에 배정될 확률이 높으므로 응답시간이 빠를 수 있지만,
  - 여전히 우선순위가 낮은 프로세스들은 우선순위가 낮은 큐에 배정될 확률이 높으므로 기아(starvation) 현상이 생길 수 있다.
  - 또한 하나의 레디큐가 아니기 때문에 여러 개의 큐의 스케쥴링에 따른 오버헤드가 존재한다.
- MFQ는 MLQ와 다르게 프로세스들이 다른 레디 큐로 이동할 수 있는 선점형(Preemptive) 스케쥴링 기법이다.
  - 프로세서 사용 정보 패턴을 바탕으로 피드백을 통해 우선순위를 조정하는 방식이어 높은 적응성과 동적인 우선순위를 가진다.
  - 하지만 여전히 낮은 우선순위를 가진 프로세스는 기아 현상을 가질 확률이 높다.
  - 장점은 짧은 수행 시간을 가진 프로세스들이 빠르게 처리될 확률이 높으며, I/O bounded 프로세스들의 우선순위가 높아서 시스템 전체의 평균 응답시간이 줄어들 확률이 높다.
  - 설계 및 구현이 복잡하고, 스케쥴링 오버헤드가 존재한다.

### MLQ ( Multi - Level Queue)

- 작업( or 우선순위)별 별도의 ready Queue를 가진다.
  - 최초의 배정된 큐에서 벗어날 수는 없다.
  - 각각의 큐는 자신만의 스케쥴링 기법을 가짐
- 큐 사이에는 우선순위 기반의 스케쥴링 사용
- 장점 : 빠른 응답 시간 (?)
  - 우선순위가 높은 작업은 빠르겠지만, 낮은 순위는 응답 시간이 느릴 것임
- 단점 : 여러 개의 큐 관리 등 스케쥴링 오버헤드 존재
  - 우선순위가 낮은 큐는 기아 현상 발생 가능

### MFQ (Multi - Level Feedback Queue)

- 프로세스의 큐 간 이동이 허용된 MLQ
- 피드백을 통해 우선 순위 조정
  - 현재까지의 프로세서 사용 정보(패턴) 활용
- 특징 : 동적인 우선순위(dynamic priority)
  - 선점형(끼어들기 가능) 스케쥴링(scheduling)
  - 짧은 실행 시간(burst time) 프로세스들 처리에 유리
  - I/O에 의해 주도(bounded)되는 프로세스들 처리에 유리
  - 프로세스에 대한 사전 정보 없이 피드백을 통해서 SPN (Shortest Process Next), SRTN (Shortest Remaining Time Next), HRRN (High Response Ratio Next) 기법의 효과를 볼 수 있음
- 단점 : 여전히 우선순위가 낮은 프로세스는 기아 현상 발생 가능
  - 설계 및 구현이 복잡하고, 스케쥴링 오버헤드가 큼
- 변형
  - 각 준비 큐마다 시간 할당량을 다르게 배정 → 프로세스들의 특성에 맞춰서 시스템 운영 가능
  - 입출력 프로세스들을 상위 단계의 큐로 이동, 즉 우선순위를 높인다 → 왜? I/O bounded 프로세스들은 상대적으로 프로세서를 많이 사용하지 않으므로 먼저 처리하면 시스템 전체의 평균 응답 시간을 줄일 수 있다.
    - 프로세스가 block될 때 상위의 준비 큐로 진입하게 한다.
    - 반대로, Compute bounded 프로세스들은 우선순위를 낮춘다.
  - 에이징 : 대기 시간이 긴 프로세스들을 우선순위를 높인다.
