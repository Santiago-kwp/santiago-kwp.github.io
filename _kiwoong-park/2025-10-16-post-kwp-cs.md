### 학습 내용 요약
- 하드 디스크는 플래터 (트렉(O)과 섹터(피자조각)), 헤드, 스핀들, 디스크 암으로 구성됨.
- 플래터는 무수히 많은 N극과 S극을 가지며 0과 1로 데이터를 저장하고, 
- 스핀들로 플래터를 돌리고 탐색 시간, 회전 지연, 전송 시간으로 데이터를 접근함.
- 플래시 메모리는 한 셀에 몇 비트를 저장할 수 있느냐에 따라 SLC, MLC, TLC, QLC로 구분됨. 
- 플래시 메모리의 읽기와 쓰기는 페이지 단위, 삭제는 블록 단위로 이뤄짐 
    - 플래시 메모리의 단위는 셀 < 페이지 < 블록 < 플레인 < 다이
    - 페이지의 상태는 free, valid, invalid로 구분되며, 한 블록에 유효하지 않은 페이지가 존재할 수 있음
    - 가비지 컬렉션을 통해 유효한 페이지만 모아서 다른 블록에 복사하여 저장하고 기존 블록을 삭제함.
- 레이드 시스템을 통해 여러 개의 보조기억장치를 하나의 논리적 저장 장치로 만들어 성능과 안전성을 높일 수 있음.
- 레이드 시스템의 기술로 여러 보조 기억장치에 나눠서 저장하는 스트라이핑, 같은 내용을 복제하는 미러링, 오류를 검출하고 오류를 복구하는 패리티 비트가 있어 이를 혼합하여 레이드 레벨을 구성함.

## 다양한 보조기억장치

대중적인 보조기억장치는 하드디스크와 플래시메모리(USB, SD카드, SSD 등)

### 하드 디스크

- 자기적인 방식으로 데이터를 저장하는 보조기억장치 → 자기 디스크(magnetic disk)의 일종으로 지칭하기도 함.
- 실질적으로 데이터가 저장되는 곳은 동그란 원판 = 플래터(platter)
    - 플래터는 자기 물질로 덮여 있어 수많은 N극과 S극을 저장함
    - N극과 S극은 0과 1의 역할을 수행
- 플래터를 회전시키는 구성 요소를 스핀들(spindle)이라고 함.
    - 스핀들이 플래터를 돌리는 속도를 분당 회전수 RPM (Revolution Per Minute) 단위로 표현
- 플래터를 대상으로 데이터를 읽고 쓰는 구성 요소는 헤드
    - 플래터 위에서 미세하게 떠 있는 채로 데이터를 읽고 쓰는, 마치 바늘같이 생긴 부품
- 헤드는 원하는 위치로 헤드를 이동시키는 디스크 암이 부착
- 일반적으로 여러 겹의 플래터로 이루어져 있고 플래터 양면을 모두 사용할 수 있음.
    - 양면 플래터를 사용하면 위아래로 플래터당 두 개의 헤드가 사용됨.
- 플래터는 트랙(track)과 섹터(sector)라는 단위로 데이터를 저장함.
    - 트랙은 플래터를 여러 동심원으로 나누었을 때 그중 하나의 원을 칭함.
    - 섹터는 트랙을 피자처럼 여러 조각으로 나눌 때 그 한 조각
    - 섹터는 하드 디스크의 가장 작은 전송 단위, 일반적으로 512바이트 정도의 크기를 가짐
- 여러 겹의 플래터 상에서 같은 트랙이 위치한 곳을 모아 연결한 논리적 단위를 실린더라고 부름.
- 연속된 정보는 보통 한 실린더에 기록됨. ⇒ 디스크 암의 움직임을 최소화
- 하드 디스크가 저장된 데이터에 접근하는 시간은 크게 탐색 시간, 회전 지연, 전송 시간으로 나뉨
    - 탐색 시간(seek time)은 접근하려는 데이터가 저장된 트랙까지 헤드를 이동시키는 시간
    - 회전 지연(rotational latency)은 헤드가 있는 곳으로 플래터를 회전시키는 시간을 의미
    - 전송 시간(transfer time)은 하드 디스크와 컴퓨터 간에 데이터를 전송하는 시간을 의미

**다중 헤드 디스크 vs 고정 헤드 디스크**

- 다중 헤드 디스크는 트랙마다 헤드가 있기 때문에 탐색 시간이 들지 않는다. 이런점에서 헤드를 움직일 필요가 없는 다중 헤드 디스크를 고정 헤드 디스크 (fixed-head disk)
- 반대로 헤드를 데이터가 있는 곳까지 움직여야 하는 단일 헤드 디스크를 이동 헤드 디스크(movable-head disk)라고 부른다.

### 플래시 메모리

- 전기적으로 데이터를 읽고 쓸 수 있는 반도체 기반의 저장 장치
- NAND 플래시 메모리 VS NOR 플래시 메모리
    - 각각, NAND 연산을 수행하는 회로(NAND 게이트)와 NOR 연산을 수행하는 회로(NOR 게이트)를 기반으로 만들어진 메모리를 뜻함.
    - 대용량 저장 장치로 많이 사용되는 플래시 메모리는 NAND 플래시 메모리. ⇒ 이번에 설명할 보조기억장치로서의 플래시 메모리는 NAND 플래시 메모리를 뜻함.
- 셀(cell)이란 플래시 메모리에서 데이터를 저장하는 가장 작은 단위  ⇒ 하나의 셀에 몇 비트를 저장할 수 있느냐에 따라 플래시 메모리 종류가 나뉨.
    - 한 셀에 1비트를 저장할 수 있는 플래시 메모리를 SLC (Single Level Cell)
    - 한 셀에 2비트를 저장할 수 있는 플래시 메모리를 MLC (Multiple LC)
    - 한 셀에 3비트를 저장할 수 있는 플래시 메모리를 TLC (Triple LC) → 4비트는 QLC
- 플래시 메모리, 하드 디스크 또한 수명이 있다. 한 셀에 일정 횟수 이상 데이터를 쓰고 지우면 그 셀은 더 이상 데이터를 저장할 수 없기 때문

**SLC 타입**

- 한 셀로 두 개의 정보(0 과 1)를 표현 가능
- 홀로 거주하는 집에 제약없이 출입이 가능하듯 SLC 타입은 MLC나 TLC 타입에 비해 비트의 빠른 입출력이 가능함.
- 수명도 MLC나 TLC 타입보다 길어서 수만에서 수십만 번 가까이 데이터를 쓰고 지우고를 반복할 수 있음.
- SLC타입은 용량 대비 가격이 높음. ⇒ 기업에서 데이터를 읽고 쓰기가 매우 많이 반복되며 고성능의 빠른 저장 장치가 필요한 경우에 사용

**MLC 타입**

- 한 셀로 4 개의 정보를 표현할 수 있음. ⇒ 대용화하기 유리
- 용량 대비 가격이 저렴함. 시중에서 많은 플래시 메모리 저장 장치들이 MLC 타입 혹은 TLC 타입으로 만들어짐

**TLC 타입**

- 한 셀당 8개의 정보를 표현할 수 있음
- SLC나 MLC 타입보다 수명과 속도가 떨어지지만 용량 대비 가격도 저렴함

**플래시 메모리의 단위 : 셀 ⇒ 페이지 ⇒ 블록 ⇒ 플레인 ⇒ 다이**

- 플래시 메모리에서 읽기와 쓰기는 페이지 단위로 이루어짐
- 삭제는 페이지보다 큰 블록 단위에서 이루어짐. 읽기/쓰기 단위와 삭제 단위가 다르다는 것이 플래시 메모리의 가장 큰 특징 중 하나
- 페이지는 3 개의 상태를 가질 수 있음. 이는 각각 Free, Valid, Invalid 상태
    - Free 상태는 어떠한 데이터도 저장하고 있지 않아 새로운 데이터를 저장할 수 있는 상태
    - Valid 상태는 이미 유효한 데이터를 저장하고 있는 상태
    - Invalid 상태는 쓰레기값이라 부르는 유효하지 않은 데이터를 저장하고 있는 상태
    - 하드 디스크와 달리 덮어쓰기가 불가능하여 Valid 상태인 페이지에는 새 데이터를 저장할 수 없음.

- 여기서 문제는 공간을 사용하지 않는데 용량을 차지하고 있어 용량 낭비임. 그렇다고 A만 삭제할 수도 없는게, 플래시 메모리에서 삭제는 블록 단위로 수행되기 때문임.
- 그래서 SSD를 비롯한 플래시 메모리는 이런 쓰레기값을 정리하기 위해 가비지 컬렉션 기능을 제공함.
- 가비지 컬렉션은 1. 유효한 페이지들만을 새로운 블록으로 복사한 뒤, 2. 기존의 블록을 삭제하는 기능. 즉, 블록 X의 모든 유효한 페이지를 새로운 블록 Y로 옮기고 블록 X를 삭제하는 것

## RAID의 정의와 종류

> 1TB 하드 디스크 4 개와 4TB 하드 디스크 한 개를 비교해보자. 1TB 하드 디스크 4 개로 RAID를 구성하면 4TB 하드 디스크 한 개의 성능과 안전성을 능가할 수 있다! 왜 이런 차이가 생기는 것일까?
> 

### RAID의 정의

- 보조기억장치에도 수명이 있기 때문에 하드 디스크와 같은 보조기억장치에 어떻게든 저장만 하면 된다는 답변은 다소 부족한 해법임.
- 이럴 때 사용할 수 있는 방법 중 하나가 바로 RAID (Redundant Array of Independent Disks).
- RAID는 주로 하드 디스크와 SSD를 사용하는 기술로, 데이터의 안전성 혹은 높은 성능을 위해 여러 개의 물리적 보조기억장치를 마치 하나의 논리적 보조기억장치처럼 사용하는 기술을 의미함.

### RAID의 종류

- RAID 구성 방법을 RAID 레벨이라 표현하는데, 대표적으로 RAID 0, 1, 2, 3, 4, 5, 6 이 있고, 그로부터 파생된 RAID 10, 50 등이 있다.

***RAID 0*** 

- 여러 개의 보조기억장치에 데이터를 단순히 나누어 저장하는 구성 방식
- 어떠한 데이터를 저장할 때 하드 디스크는 번갈아 가며 데이터를 저장함. 즉, 저장되는 데이터가 하드 디스크 개수만큼 나뉘어 저장
- 마치 줄무늬처럼 분산되어 저장된 데이터를 스트라입(stripe, 줄무늬)이라 하고, 분산하여 저장하는 것을 스트라이핑(striping)
- 스트라이핑되면 저장된 데이터를 읽고 쓰는 속도가 빨라짐. ⇒ 하나의 대용량 저장 장치를 이용했더라면 여러 번에 걸쳐 읽고 썼을 데이터를 동시에 읽고 쓸 수 있기 때문.
- ⚙️ 왜 속도가 빨라질까?
    
    ✅ 단일 디스크일 경우
    
    - 1GB 파일을 **한 디스크가 혼자** 읽고 써야 함
    - 디스크의 **물리적 한계**(회전 속도, 헤드 이동 등) 때문에 시간이 오래 걸림
    
    ✅ 스트라이핑된 경우
    
    - 4개의 디스크가 **동시에 병렬로 작업**
    - 각 디스크는 256MB만 처리하면 되므로
    - 전체 작업 시간이 **1/4 수준으로 단축**
    
    ➡️ 즉, **병렬 처리 덕분에 속도가 빨라지는 것**!
    
- 저장된 정보가 안전하지 않다는 단점 존재. 하나의 디스크에서 문제가 생기면 다른 모든 하드 디스크의 정보를 읽는 데 문제가 생길 수 있음 ⇒ RAID 1 등장

***RAID 1***

- 복사본을 만드는 방식. 마치 거울처럼 완전한 복사본을 만드는 구성이기에 미러링이라고 부름.
- RAID 0 처럼 데이터 스트라이핑이 사용되긴 하지만, 4개의 하드 디스크의 경우 두 개의 하드 디스크와 동일한 내용을 저장함. ⇒ RAID 1에 어떠한 데이터를 쓸 때는 원본과 복사본 두 군데에 씀. 쓰기 속도는 RAID 0 보다 느림
- 복구가 매우 간단함.
- 하드 디스크 개수가 한정되었을 때 사용 가능한 용량이 적어지는 단점 존재.

***RAID 4***

- RAID 1 처럼 완전한 복사본을 만드는 대신 오류를 검출하고 복구하기 위한 정보를 저장한 장치를 두는 구성 방식. 이때 ‘오류를 검출하고 복구하기 위한 정보’를 패리티 비트(parity bit)라고 함.
- 패리티를 저장한 장치를 이용해 다른 장치들의 오류를 검출하고, 오류가 있다면 복구함.
    - 패리티 비트는 본래 오류 검출용 정보지만, RAID에서는 오류 복구도 가능하다.
- RAID4는 RAID1 보다 적은 하드 디스크로도 데이터를 안전하게 보관할 수 있음.

***RAID 5***

- RAID 4에서는 어떤 새로운 데이터가 저장될 때마다 **패리티를 저장하는 디스크에도 데이터를 쓰게 되므로 패리티를 저장하는 장치에 병목 현상이 발생**한다는 문제점 존재 (패리티를 저장한 장치를 따로 두는 방식))
- **패리티 정보를 분산하여 저장**하는 방식으로 RAID 4의 문제인 병목 현상을 해소함.

***RAID 6***

- 기본적으로 RAID 5와 같으나, 서로 다른 두 개의 패리티를 두는 방식
- 오류를 검출하고 복구할 수 있는 수단이 두 개가 생긴 셈.
- 다만 새로운 정보를 저장할 때마다 함께 저장할 패리티가 두 개 이므로, 쓰기 속도는 RAID 5보다 느림.
- RAID5는 데이터 저장 속도를 조금 희생하더라도, 데이터를 안전하게 보관하고 싶을 때 사용한다.
