## 1. S/W 차원에서의 상호 배제

### Dekker’s Algorithm

**기본 개요**

- 2개 프로세스 간 상호 배제를 보장하는 최초의 알고리즘
    - turn: 두 프로세스 중, 현재 임계 영역에 진입할 차례인 프로세스
    - flag: true/false값을 통해 임계영역 진입 가능 여부를 표현
    - 두 프로세스의 flag값이 모두 true일 때도 상호배제/진입 조건을 충족

![lec13_dekker.png](/assets/images/lec13_dekker.png)

- 알고리즘 수행 양상
    - while문 내부의 if문 → 상호배제 기법의 요건 중 진입, 상호배제 구현
        - 두 프로세스 모두 임계 영역에 진입할 수 있을 때도 turn값을 통해 현재 프로세스가 진입할 차례인지를 확인함으로써 한 프로세스만 임계 영역에 진입하는 것을 보장
        - 내부의 while문에서는 임계 영역에 진입한 프로세스가 존재하거나, 현재 프로세스가 진입할 차례가 아닐 경우, 임계 영역에 진입한 다른 프로세스의 작업이 완료될 때까지 대기
    - 임계영역에서의 작업이 끝난 프로세스는 다른 프로세스에게 턴을 넘김
    (임계 영역 이후 turn, flag값 변경)

### Peterson’s Algorithm

**기본 개요**

- Dekker’s Algorithm을 간략화한, 2개 프로세스 간 상호배제를 보장하는 알고리즘

![lec13_peterson.png](/assets/images/lec13_peterson.png)

- 알고리즘 수행 양상
    - 두 프로세스 모두 처음부터 turn값을 변경
        - 상대에게 차례를 먼저 양보한 프로세스부터 임계 영역에 진입
        - 임계 영역에 진입하지 못한 프로세스는 다른 프로세스의 작업이 끝날 때까지 대기
    - 임계 영역에서의 작업이 종료되면 flag값만 변경

### Dijkstra’s Algorithm

- N개 프로세스 간 상호배제를 보장하는 최초의 알고리즘

![lec13_dijkstra.png](/assets/images/lec13_dijkstra.png)

- 알고리즘 수행 양상
    - 각 프로세스별 flag값은 boolean 대신 3개의 정수값을 사용
    → 프로세스의 임계 영역 진입 여부를 3단계로 나누어 표현
    - 실행시간이 가장 짧은 프로세스부터 CPU 리소스를 할당

cf) 다익스트라 알고리즘 외에도 N개 프로세스에 관한 다양한 상호배제 알고리즘이 존재

- 크누스, 램포트, 핸슨 등…

### S/W 차원에서의 상호배제의 문제점

- 구현이 복잡하고, 중첩된 반복문을 사용하여 속도가 느림
- 작성한 코드를 실행하는 도중 인터럽트가 발생하여 실행이 중단될 수 있으며, 이를 처리하기 위한 오버헤드가 발생할 수 있음
- Busy Waiting 문제 발생
    - 임계 영역으로의 진입이 불가능할 때, 진입이 가능할 때까지 무한 반복하면서 재시도한다는 점에서 비효율적

## 2. H/W 차원에서의 상호 배제

### TestAndSet(TAS) instruction 개요

- target의 현재 값을 true로 설정하면서 이전의 lock값을 반환하는 작업을 수행하는 단일 기계어
- 1개의 기계어를 사용하므로, 실행 중 다른 기계어의 인터럽트를 받지 않음이 보장됨
    
    ![lec14_tas.png](/assets/images/lec14_tas.png)
    

### TAS Instruction 사용 - 프로세스가 2개

![lec14_tas_2.png](/assets/images/lec14_tas_2.png)

- boolean 타입인 1개의 lock을 사용하여 두 프로세스 간 상호 배제를 수행
- 한 프로세스가 임계영역에 진입할 때, TAS Instruction을 실행하여 lock의 값을 true로 변경하여 다른 프로세스가 임계 영역에 진입하는 것을 방지
- 3개 이상의 프로세스에서는 한정 대기(Bounded Waiting) 조건 위배 가능성 존재
    - 한 프로세스의 작업이 종료된 후 새로운 프로세스가 추가되거나 남은 프로세스를 실행하는 과정에서, 특정한 프로세스의 실행 순서가 계속 밀리면서 무한정 대기하게 되는 문제가 발생할 수 있음

### TAS Instruction 사용 - 프로세스가 3개 이상

![lec14_tas_n.png](/assets/images/lec14_tas_n.png)

- 알고리즘 수행 양상
    - 이미 임계 영역에 진입한 프로세스가 있다면 대기상태를 유지
        - 캡처의 2~5번에 해당
        - 현재 프로세스의 대기상태 유지 여부를 waiting 플래그로 표현
        - lock을 걸고 대기상태를 유지하기 위해 TAS Instruction을 사용
    - 이미 대기 중인 다른 프로세스가 있다면, 해당 프로세스는 대기상태를 해제하고 임계 영역에 진입
        - 캡처의 6~9번에 해당
        - 다음에 임계 영역에 진입할 프로세스가 현재 프로세스라면 걸어둔 lock을 해제

### H/W 차원에서의 상호배제의 장단점

- S/W 차원에서의 상호배제 알고리즘에 비해 구현 코드가 단순
- 여전히 Busy Waiting 문제가 존재
    - 임계 영역으로의 진입이 불가능한 경우에는 무한 루프를 통해 진입이 가능할 때까지 계속 반복한다는 점에서 비효율적
