## HTTP 메시지 요약

- HTTP 메시지는 다음의 요소들로 구성
    - 시작 줄: HTTP 요청/응답 메시지의 핵심 정보를 담은 1개의 줄
    - HTTP 헤더: 시작 줄의 요청/응답에 관한 부가정보를 제공
    - 공백 라인: HTTP 헤더와 메시지 바디 사이를 구분
    - 메시지 바디(→ 페이로드): HTTP 메시지를 통해 전달할 실제 데이터
- HTTP 메시지는 그 구조가 단순하지만, 필요에 따라 임의의 헤더를 추가하는 것이 가능하기 때문에 확장성이 높음

## HTTP 메시지 구조 개요

- HTTP 메시지는 시작 줄, 헤더, 공백 라인, 메시지 바디(→ 페이로드)로 구성
- 헤더와 메시지 바디 사이에 공백 라인을 두어 두 영역을 구분

![http_message_1.png](/assets/images/http_message_1.png)

## 시작 줄

- HTTP 메시지의 종류에 따라 세부적인 차이가 존재하지만, 1개의 줄로만 이루어져 있다는 점은 동일
- **요청 메시지의 시작 줄**
    - 클라이언트가 서버에게 전송한 요청 사항에 해당
    - 순서대로 요청 메서드, 요청한 리소스, HTTP 버전 정보를 제공
    
    ![http_message_2.png](/assets/images/http_message_2.png)
    
    - 요청 메서드: 요청 처리를 위해 서버가 수행할 행위(GET, POST, PUT, PATCH, DELETE 등)
    - 요청한 리소스
        - 절대경로(`/` 로 시작)와 쿼리로 구성
        - URL의 구성 요소 중 path와 query를 포괄하는 문자열에 해당
    - HTTP 버전 정보: 요청에 사용된 http 버전
    
- **응답 메시지의 시작 줄(= 상태 줄)**
    - 클라이언트의 요청 사항에 관한 서버의 응답 결과에 해당
    
    ![http_message_3.png](/assets/images/http_message_3.png)
    
    - 순서대로 HTTP 버전, 상태 코드, 상태 코드에 관한 설명을 제공
    - HTTP 상태 코드: 요청 처리 성공/실패 또는 리다이렉트 여부를 나타내는 세 자리 숫자
        - 2XX → 요청 처리 성공
        - 3XX → 리다이렉트
        - 4XX → 클라이언트 오류로 인한 요청 처리 실패
        - 5XX → 서버 오류로 인한 요청 처리 실패
    - 이유 문구: 상태 코드에 관한 간략한 설명

## HTTP 헤더

- HTTP 메시지를 전송하기 위해 필요한 모든 부가정보를 제공하는 영역
    - 메시지 바디의 내용, 메시지 바디의 크기, 압축, 인증, 요청 클라이언트(브라우저) 정보, 서버 애플리케이션 정보, 캐시 관리 정보...
- 클라이언트와 서버의 필요에 따라 임의의 HTTP 헤더를 추가할 수 있으므로 확장에 유리
    - 즉, HTTP 헤더에 관한 일종의 커스터마이징이 가능하다.
- [HTTP 헤더 - MDN 공식 문서](https://developer.mozilla.org/ko/docs/Web/HTTP/Reference/Headers)

## 메시지 바디(= 페이로드)

- HTTP 메시지를 통해 실제로 전송되는 데이터에 해당하는 부분

![http_message_4.png](/assets/images/http_message_4.png)

- 바이트(byte) 단위로 표현 가능한 모든 데이터를 저장할 수 있음
    - 텍스트, 영상, 사진, JSON, XML
    - 즉, 이진 데이터로 변환할 수 있는 데이터라면 HTTP 메시지를 통해 전송 가능
    - 멀티미디어 데이터 전송은 `HTTP/1.0`(1996) 버전일 때부터 지원
