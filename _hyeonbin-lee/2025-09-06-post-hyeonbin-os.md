## FCFS(First-Come-First-Service)

- 선착순 알고리즘
    - Ready Queue(준비 큐)에 도착한 시간을 기준으로 했을 때, 먼저 온 프로세스부터 CPU 리소스를 할당하는 방식
- 비선점형 스케줄링 방식
    - 먼저 온 프로세스의 실행이 종료될 때까지, 나중에 온 프로세스는 CPU 리소스를 이용할 수 없음
- 일괄 처리 시스템에 적합하나, 대화형 시스템에는 부적합
    - 일괄 처리 시스템에서는 실행된 순서대로 누적된 프로세스들을 한번에 처리하므로, 응답 시간이 중요하지 않음
    - 대화형 시스템에서는 즉각적인 응답이 중요
        - 나중에 실행되었더라도 처리 시간이 짧은 프로세스를 먼저 처리하도록 순서를 조정해야 응답 시간을 개선 가능
        - 즉, 신속히 작업을 처리할 때는 프로세스 실행 순서 ≠ 처리 순서일 가능성이 존재
- FCFS의 장단점
    - 준비 큐에 도착한 순서를 유지하므로, 스케줄링 과정에서 불필요한 비용(overhead)가 발생하지 않아 CPU 리소스를 효율적으로 사용 가능
    - Convoy Effect 발생 → 평균 응답 시간 증가
        - 먼저 실행되는 프로세스의 수행시간이 길 경우, 나중에 실행될 프로세스들의 실행이 정체되는 현상
        - 나중에 실행되는 프로세스일수록 대기 시간이 실행 시간보다 커지는 문제가 발생할 수 있음

![lec9_fcfs.png](/assets/images/lec9_fcfs.png)

cf. 1) 반환 시간(Turnaround Time, TT)

- 프로세스가 대기큐에 들어올 때부터 실행이 완료될 때까지의 시간
- 대기 시간(waiting time) + 실행 시간(burst time)

cf. 2) 정규화된 반환 시간(Normalized TT, NTT)

- 반환 시간을 실행 시간으로 나눈 값
- 정규화(Normalization)
    - ‘시작점과 범위가 서로 다른 대상에 대한 비교를 원활히 수행하기 위해, 비교 기준을 통일하는 것’ 정도로 이해
    - 즉, NTT는 실행 시간과 반환 시간이 서로 다른 프로세스마다 실제 실행에 걸린 시간을 서로 비교하기 위한 지표

## RR(Round-Robin)

- **리소스 사용 제한시간**을 부여한 선착순 스케줄링 방식
    - 준비 큐 도착 시간을 기준으로 프로세스에게 CPU 리소스를 할당
    - 특정 프로세스가 자원을 독점하는 것을 방지하기 위해 리소스를 할당할 때마다 일정한 제한 시간을 부여
    - **리소스 사용 시간이 만료되었으나 작업이 완료되지 않은 프로세스는 다시 준비 큐의 맨 뒤로 이동하여 대기**
- 선점형 스케줄링 방식
    - 먼저 온 프로세스의 CPU 사용 시간이 끝나면, 해당 프로세스의 작업이 완료되지 않아도 다음 프로세스에게 강제로 CPU 리소스를 할당
- 대화형/시분할 시스템에 적합
    - 모든 프로세스가 균등하게 CPU 리소스를 할당받을 수 있으므로, 실행 시간이 짧은 프로세스를 신속히 처리 가능
    - 프로세스에게 CPU를 할당할 때마다 일정한 리소스 사용 시간을 부여
    → 프로세스의 실행 시간을 일정 시간 간격으로 분할
- 성능 결정 지표: 리소스 사용 시간 할당량(time quantum)
    - 너무 크게 설정 → FCFS 스케줄링과 동일한 문제 발생
    - 너무 작게 설정 → 컨텍스트 스위칭을 처리하는 비용이 크게 증가
- RR의 장단점
    - FCFS의 Convoy Effect 문제 해소 가능
        - 모든 프로세스에게 리소스 이용 기회를 공평하게 부여하여 특정 프로세스의 리소스 독점을 방지
        - FCFS보다 평균 응답 시간이 짧음
    - 빈번한 컨텍스트 스위칭으로 인해, 이를 처리하기 위한 추가비용 증가

## SPN(Shortest-Process-Next)

- 실행 시간이 짧은 프로세스부터 CPU 리소스를 할당하는 방식
    - SJF(Shortest Job First)라고도 불림
- 비선점형 스케줄링 방식
    - 실행 중인 프로세스가 종료될 때까지, 실행 시간이 긴 프로세스는 CPU 리소스를 이용할 수 없음
- SPN의 장점
    - 실행 시간이 짧은 프로세스부터 실행할 수 있어 평균 대기 시간 및 응답 시간 단축 가능
    - 스케줄링의 대상이 되는 프로세스 수를 최소화하여 시스템 효율 개선
        - 실행 시간이 빠른 프로세스부터 처리하므로, 여러 개의 프로세스를 실행하기 위해 할당되는 메모리를 절약
- SPN의 단점
    - **Starvation(기아 현상)**
        - 프로세스의 실행 시간이 길수록 CPU를 할당받기 위한 순위가 계속 뒤로 밀리는 문제
        - Aging 기법을 적용하여 기아 현상이 발생한 프로세스의 순위를 높임으로써 해소 가능(→ HRRN 스케줄링)
    - 별도의 실행시간 예측 기법이 요구됨
        - 실행 시간을 기준으로 스케줄링을 수행하지만, 실제로는 프로세스의 정확한 실행 시간을 파악하기 어렵기 때문

---

## SRTN(Shortest-Remaining Time Next)

- SPN을 변형한 스케줄링 방식
    - 남은 실행 시간이 더 적은 프로세스부터 CPU 리소스를 할당받는 방식
- 선점형 스케줄링 방식
    - 잔여 실행 시간이 더 적은 프로세스가 준비 큐에 추가되는 즉시, 해당 프로세스에게 CPU 리소스를 최우선적으로 할당
- SRTN의 장점 - SPN의 장점을 극대화
    - 실행 시간이 짧은 프로세스에게 리소스를 즉시 할당 가능
    - 평균 대기시간과 응답 시간이 짧음
    - 스케줄링 및 프로세스에 사용되는 메모리를 절약할 수 있음
- SRTN의 단점 - 실제 구현 및 사용이 어려움
    - 잔여 실행 시간을 계속 추적하고, 이에 따라 컨텍스트 스위칭을 수행하기 위한 추가비용이 발생
    - 각 프로세스별 잔여 실행 시간을 추적하는 비용도 발생

---

## HRRN(High-Response-Ratio-Next)

- SPN을 변형한 스케줄링 방식 → 응답률이 높은 순서대로 스케줄링
    - 기본적으로는 실행 시간이 짧은 프로세스부터 CPU를 할당하는 방식
    - 기아 현상을 방지하기 위해, Aging 개념을 추가적으로 도입
        - 프로세스의 대기 시간을 고려하여 기회를 제공
    - **SPN과 SRTN 사이의 현실적인 절충안**
- 비선점형 스케줄링 방식
    - CPU 리소스를 할당받은 프로세스의 실행이 종료될 때까지 다음 순번의 프로세스들은 대기
- HRRN의 장점
    - 실행 시간이 짧은 프로세스부터 실행할 수 있어 평균 대기 시간 및 응답 시간 단축 가능
    - 스케줄링의 대상이 되는 프로세스 수를 최소화하여 시스템 효율 개선
    - **SPN의 기아 현상 문제를 해소**
- HRRN의 단점
    - 별도의 실행시간 예측 기법이 요구됨

cf) 응답률(Response Ratio)

- 응답률 = (대기시간+실행시간)/실행시간
- 순수 실행 시간에 대해 실제 응답까지 걸린 시간의 비율을 의미
    - 실행시간이 일정하더라도 대기시간이 증가하면 응답률도 증가
- Aging 개념이 HRRN 스케줄링에 실제로 적용되는 부분

## MLQ(Multi-level Queue)

- 작업/우선순위에 따라 여러 개의 Ready Queue를 사용
    - 할당된 프로세스는 최초 배정된 큐에서 다른 큐로 변경되지 않음
    - 각각의 큐마다 스케줄링 기법을 다르게 적용 가능
- 여러 개의 Ready Queue 사이에서는 우선순위 기반 스케줄링 적용
- MLQ의 장단점
    - 프로세스의 중요도에 따라 응답 시간의 편차가 커질 수 있음
        - 우선순위가 높은 큐에서는 응답시간이 짧음
        - 우선순위가 낮은 큐일수록 기아 현상으로 인해 응답 시간이 증가
    - 시스템상의 변화를 반영하기 어려움

## MFQ(Multi-level Feedback Queue)

- 프로세스의 Queue 간 이동을 허용한 MLQ
    - 현재까지의 CPU 사용 정보(feedback)를 반영하여 프로세스의 우선 순위를 동적으로 조정할 수 있음
- 선점형 스케줄링 방식
- MFQ의 장점
    - feedback을 프로세스의 우선순위에 반영하므로, 프로세스에 관한 사전 정보 없이도 SPN, SRTN, HRRN 기법을 구현할 수 있음
- MFQ의 단점
    - 설계와 구현이 복잡하고, 스케줄링 부하가 증가
    - 기아 문제가 발생할 수 있음
- MFQ의 변형 예시
    - 각 Ready Queue마다 시간 할당량을 다르게 부여
    - 입출력 위주 프로세스에게 높은 우선순위를 부여
        - 입출력 작업은 대체적으로 실행시간이 짧음 
        → I/O Block이 발생할 때마다 상위 큐로 이동시켜 신속히 처리
    - Aging 기법 적용
        - 대기시간이 지나치게 증가한 프로세스를 상위 큐로 이동
    - 그 외 고려 가능한 사항들
        - 사용할 Ready Queue의 개수
        - 각 Queue마다 적용할 스케줄링 알고리즘
        - 우선순위 조정 기준
        - 최초로 Queue를 배정하는 기준
