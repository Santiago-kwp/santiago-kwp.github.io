## 📋 상황 #
> 로컬 브랜치에 변경 사항이 없을 때 메인 브랜치의 최신 작업 상황을 가져오려면?
 
>먼저 `git checkout gh-pages`를 통해 메인 브랜치로 이동한 후 `git fetch origin` 명령어로 원격 저장소의 변경 사항을 가져온 뒤, 
`git merge origin/gh-pages` 명령어로 로컬 `gh-pages` 브랜치에 병합하고, 
마지막으로 git checkout [자신이 작업하던 브랜치] 명령어로 다시 작업하던 브랜치로 이동하여 `git merge gh-pages`을 실행하거나, 
또는 `git rebase gh-pages`을 통해 최신화할 수 있습니다.


>작업 브랜치를 최신 메인 브랜치로 업데이트하는 절차
원격 저장소의 변경 사항 가져오기: 현재 작업 중인 브랜치에 변경 사항이 없을 때 원격 저장소의 메인 브랜치 최신 내용을 가져오려면, 다음 명령어를 사용합니다.
```
git fetch origin
```    
`git fetch origin`: 원격 저장소(origin)에서 모든 변경 사항을 가져와서 로컬에 `origin/gh-pages`과 같은 원격 브랜치 형태로 저장합니다.
현재 작업 브랜치로 이동: 메인 브랜치의 최신 내용이 원격 저장소에서 로컬로 가져와졌다면, 다시 작업 중이던 브랜치로 전환해야 합니다.

### git fetch vs git pull
>`git pull` 은 `git fetch`와 `git merge`를 결합한 명령어에요. 이 두 명령어의 차이를 이해하는 게 핵심!

`git fetch origin` : `git fetch origin`은 원격 저장소(origin)의 최신 상태 정보를 로컬 저장소로 가져와요.

- 이 명령을 실행해도 현재 작업 중인 브랜치는 변하지 않음. * 단지 원격 저장소의 최신 커밋 이력(메인 브랜치의 최신 변경 사항 등)을 로컬에 다운로드하는 역할을 함.
- 이후 git diff main origin/main 같은 명령을 사용해서 로컬 브랜치와 원격 브랜치의 차이를 확인하거나, 직접 병합(merge) 또는 리베이스(rebase)를 할 수 있음.
- 즉, 원격의 변경 사항을 확인만 하고 아직 내 브랜치에 적용하지 않을 때 사용

`git pull` : `git pull`은 원격 저장소의 최신 커밋을 가져와서 즉시 현재 브랜치에 병합(merge).
- `git pull`은 `git fetch`를 먼저 실행해서 원격의 최신 이력을 가져온 다음, 자동으로 `git merge`를 실행해서 가져온 변경 사항을 현재 브랜치에 합치는 두 단계의 작업을 한 번에 수행해요.
- 이 과정에서 충돌(conflict)이 발생하면 직접 해결해야 함.
- 즉, 원격의 최신 상태를 내 브랜치에 바로 적용하고 싶을 때 사용함.

|  | `git fetch origin` | `git pull` |
| --- | --- | --- |
| **주요 역할** | 원격 저장소의 최신 이력만 가져오기 | 원격 이력을 가져와 현재 브랜치에 즉시 병합하기 |
| **로컬 브랜치 상태 변화** | **변화 없음** | **최신 이력이 병합되며 변화** |
| **장점** | 병합 전 변경 사항을 먼저 확인하고 신중하게 적용할 수 있음 | 한 번의 명령으로 빠르게 최신화 가능 |
| **단점** | 병합을 위해 추가 명령(`merge` 또는 `rebase`) 필요 | 예상치 못한 변경이 바로 적용될 수 있음 |

```
git checkout [자신이 작업하던 브랜치 이름]
```
   
메인 브랜치의 최신 내용을 현재 브랜치에 통합: 이제 메인 브랜치의 변경 사항을 현재 작업 브랜치에 적용할 차례입니다.
`git merge gh-pages` 사용:
```
git merge gh-pages
```
이 명령어는 메인 브랜치의 변경 사항을 현재 브랜치에 병합하여 히스토리를 합칩니다. 충돌이 발생할 수 있으며, 충돌을 해결해야 합니다. `git rebase gh-pages` 사용.
```
git rebase gh-pages
```
        
이 명령어는 현재 브랜치의 커밋들을 메인 브랜치의 최신 커밋 뒤에 다시 쌓아 올리는 방식으로, 선형적인 히스토리를 유지하며 변경 사항을 적용합니다.

✍ 팁:
작업 전에 항상 git fetch origin 명령어를 실행하여 원격 저장소의 최신 상태를 확인하는 습관을 들이면 좋습니다.
git rebase 사용 시에는 로컬 브랜치의 히스토리가 변경될 수 있으므로 주의해야 합니다.
