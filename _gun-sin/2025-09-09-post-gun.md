## 2025.09.09. MVC구조 완전 정복

## 1. MVC란

MVC는 Model,View, Controller의 약자이다.

| 구성요소 | 역할 | 비유 |
| --- | --- | --- |
| Model | 데이터를 저장,처리 | 컴퓨터 본체: 모든 정보를 저장,처리 |
| View | 사용자에게 데이터 입,출력 | 모니터: 사용자에게 보여주는 창 |
| Controller | 사용자의 행동을 처리하고 Model과 View를 연결 | 케이블: 요청이 있을 때마다 전달 및 연결 |

하나의 애플리케이션, 프로젝트를 구성할 때 구성요소를 3가지의 역할로 구분한 패턴이다. View와 Controller는 Model이 있어야 하지만 모델은 화면 표시나 컨트롤러와는 독립적이다.

- 모델에 대한 작업을 할 때 로직이나 화면상 표현에 영향을 주지 않는다는 뜻이다.

## 2. Model(모델)

애플리케이션의 정보, 데이터를 나타낸다. 데이터 베이스. 초기화 값, 변수등을 뜻한다.

## 2-1. Model의 특징, 규칙

### 1. 사용자가 편집하기 원하는 모든 데이터를 가지고 있어야 한다.

모델은 CRUD를 담당하기 때문에 가지고 있지 않은 데이터는 처리 할 수 없으므로 모든 데이터를 가지고 있어야 한다.

### 2. View나 Controller에 대해서 어떤 정보도 알지 말아야 한다.

쉽게 말해서는 역할 분리이다. 모델은 데이터 관리만 하고, 뷰는 보여주는 역할만 하고, Controller는 흐름을 제어하는 역할만을 하는 것이다. 만약 뷰나 컨트롤러가 직접 데이터를 가지고 있으면 구조가 엉키고 유지 보수하기 어려워진다. 모델이 데이터를 독점하면, 다른 컴포넌트(부품)는 그 데이터를 요청만 하면 되기 때문에 코드가 간결해진다.

### 3. 필요한 데이터가 있으면 모델을 통해서 요청한다.

각각의 컴포넌트들은 모든 데이터들을 모델을 통해서 요청하게 되면 동일한 데이터를 받을 수있으므로 일관성 유지에 유리하다.

## 3. View(뷰)

input 텍스트, table, 체크 박스 등과 같은 사용자 인터페이스 요소를 나타낸다. 쉽게 말해서 사용자로부터 데이터의 입력과 출력을 담당한다고 볼 수 있다. 즉 데이터를 기반으로 사용자들이 볼 수 있는 화면이다.

## 3-1. View의 특징,규칙

### 1. Model이 가지고 있는 정보를 따로 저장해서는 안된다.

화면에 ‘나는 자바가 너무 어려워요’ 를 표시 하기 위해서 모델이 가지고 있는 문자열 데이터를 전달 받게 될 텐데, 그 정보를 임의로 뷰 내부에 저장하면 안된다.(모든 데이터 저장은 모델에서 할 텐데 뷰에서도 저장하면 다중 저장이 되어서 유지 보수 하기 어려워진다.) 즉 단순히 입력 및 출력하라는 명령을 받으면 입, 출력만 하고 던져야 한다.

### 2. Model과 Controller에게 간섭 받으면 안된다.

사람과 비유하면 된다. 나는 내 할 일을 잘하고 있는데 간섭 받으면 할 수 있던 일도 더 많은 시행착오를 격게 된다. 따라서 그냥 본인이 할 역할에 최선을 다하면 된다.

### 3. 변경이 일어나면 변경 통지에 대한 처리 방법을 구현해야만 한다.

변경이 일어났을 때 이를 누군가에게 변경 사항을 알려줘야 하는 방법이 있어야 한다. 화면에서 사용자가 화면 표시된 내용을 변경하게 되면 이를 모델에게 알려줘서 모델에 있는 데이터를 모델이 바꾸게 해야 한다. 여기서 View 는 데이터를 직접 변경하는 것이 아니라 모델에게 바꾸라고 말해주는 것과 같다.

## 4. Controller,컨트롤러

데이터(Model)와 사용자 인터페이스 요소(View)를 잇는 다리 역할을 한다. 즉 사용자가 마우스 or 키보드 등을 통해서 데이터를 수정하는 행위를 처리하는 부분이다.

## 4-1. Controller의 특징,규칙

### 1. 모델이나 뷰에 대해서 알고 있어야 한다.

모델이나 뷰는 서로의 존재를 모르고, 변경사항이 있으면 전달 or 받는 기능만 가지고 있는데 이를 중간에 서 중재해주는 Controller는 모델과 관련된 뷰에 대해서 알고 있어야 한다.

쉽게 말해서 컨트롤러는 정보를 알아야 그에 해당하는 뷰와 모델을 연결해줄 수있는거지 모르면 해당하지 않은 뷰와 모델을 연결 시켜주는 오류가 발생할 수 있다.

### 2. 모델이나 뷰의 변경을 감시해야 한다.

모델이나 뷰에서 보내주는 변경 통지를 받으면 이를 해석해서 각각의 구성요소들에게 보내줘야 한다.

## 요약

1. View를 통해서 사용자에게 데이터 입력을 받으면 뷰는 “데이터 처리 필요” 라고 외치고 
2. 이를 들은 Controller는 데이터 저장소인 Model에게 너 “데이터 처리해” 말해주고
3. Model은 CRUD중 해당하는 처리를 하고 “나 처리했어” 라고 외치면
4. Controller는 View에게 데이터 처리 완료 라고 말해주며’
5. View는 “사용자에게 주인님 다했어요” 라고 말해준다.
