## 1강. 데이터 베이스 알아보기

- 데이터 베이스: 데이터의 집합이다.
- DBMS: 데이터 베이스를 운영하는 소프트웨어 ex) mysql, 오라클, sql서버, mariaDB등이 있다.
    
               대용량의 데이터를 관리하거나 여러 사용자와 공유한다.
    
- 관계형 DBMS: 테이블이라는 최소 단위로 구성되며 하나 이상의 열과 행으로 이루어져 있다.

| 각 열의 이름들 ⇒ | 아이디 | 이름  | 연락처 |
| --- | --- | --- | --- |
| 1행 | 제발 살려줘 | 신건 | 010-1818-1818 |
| 2행 | 차라리 죽여줘 | 봉수영 | 010-7777-7777 |
| 3행 | 한방에 보내줘 | 차무식 | 010-1577-1577 |
|  | 1열  | 2열 | 3열 |

표 자체가 하나의 테이블이다.(데이터 베이스 최소 단위)

## 1장. 마무리

- 데이터 베이스는 데이터의 집합이며 DBMS는 데이터 베이스를 운영/ 관리하는 프로그램이다.
- 테이블은 데이터 베이스의 최소 단위로, 하나 이상의 열과 행으로 구성되어있습니다.
- SQL은 데이터베이스를 구축, 관리하고 활용하기 위해서 사용되는 언어입니다.

## 2-1강. 건물을 짓기 위한 설계도: 데이터베이스 모델링

이 번 강의는 우리가 데이터베이스를 공부하는 것을 여행이라고 생각 하였을 때 우리가 갈 여행지를 헬리콥터 타고 미리  한 바퀴 도는 것이라고 생각 하면 된다.

- 데이터베이스 모델링: 건물을 짓기 위해서 착공 전에 설계도를 만드는 것이다.
- 프로젝트: 현실 세계에서 일어나는 업무를 컴퓨터에  옮겨 놓는 과정, 대규모 소프트웨어를 작성하기 위한 전체 과정
- 프로젝트 진행 단계:  폭포수 모델
    
    
    |  | 폭포수 모델 |  |
    | --- | --- | --- |
    | 1단계 | 프로젝트 계획 | 슈퍼 마켓의 물건들을 온라인으로 판매하기 위한 계획단계 |
    | 2단계 | 업무 분석 | 슈퍼마켓에서 업무가 어떻게 돌아가는지 파악 |
    | 3단계 | 시스템 설계 | 앞에서 정리한 업무 분석을 컴퓨터에 적용하기 위해서 정비 |
    | 4단계 | 프로그램 구현 | 완성한 시스템 설계의 결과를 프로그래밍 언어로 코딩 |
    | 5단계 | 테스트 | 프로그램에 오류가 없는지 점검하는 과정 |
    | 6단계 | 유지 보수 | 실제 온라인 쇼핑몰을 운영하면서 문제점 보완 |

 ex) 쇼핑몰 데이터베이스가 있다.

데이터 베이스 안에 한 개 이상의 테이블이 있다.

여기서 는 회원테이블과 제품 테이블 두개 가 있다고 예시를 들어보겠다.

— 회원테이블

| 아이디(pk) | 회원 이름 | 주소 |
| --- | --- | --- |
| tess | 나훈아 | 경기 부천시 중동 |
| hero | 임영웅 | 서울 은평구 증산동 |
| iyou | 아이유 | 인천 남구 주안동 |
| jyp | 박진영 | 경기도 고양시 장항동 |

— 제품 테이블

| 제품 이름(pk) | 가격 | 제조 일자 | 제조회사 | 남은 수량 |
| --- | --- | --- | --- | --- |
| 바나나 | 1500 | 21-07-01 | 델몬트 | 17 |
| 카스 | 2500 | 21-07-01 | OB | 3 |
| 삼각김밥 | 800 | 21-07-01 | CJ | 22 |
- 회원 테이블은 행이 4개이므로 4건의 데이터가 있다.
- 제품테이블은 행이 3개이므로 3건의 데이터가 있다.
- 기본키: primary key(pk) 각각의 행을 구분하는 유일한 값

ex) 네이버 회원가입 할 때 아이디 중복 확인하고 중복된 아이디는 사용 불가이다.

그래서 아이디만 알면 그 회원의 정보를 알 수 있다. 

현재 쇼핑몰 데이터베이스를 관리하는 오태식이는 회원 테이블에서 기본키(pk)를 아이디로 정했고

제품 테이블에서는 제품 이름으로 정한 것이다.

- 네이버 회원이면서 네이버 아이디가 없는 사람이 있는가?
- 네이버 아이디는 중복이 가능한가?

기본 키를 정하는 전제 조건은 네이버 아이디와 똑같다.

```smalltalk
1. 중복이 되면 안된다.(uniqe)
2. 없으면 안된다.(not null)
3. 행과 열중 열에다가 지정해야한다.
```

## 2-3강 데이터베이스 객체

### 데이터베이스 객체란

데이터 베이스 안에 들어 갈 수 있는 object이다.

Ex)Table, 뷰,인덱스, 스토어드프로시저

### 인덱스란

데이터를 조회 할 때 빠르게 조회 할 수 있도록 도와주는 데이터베이스 객체

- 찾아보기 개념과 동일한 개념

만약에 책이 400만 권이 있고 이 중에 아이유가 들어가는 책을 찾는다고 가정해보자. 그러면 데이터도 400만 건이 있는 것이다.

여기서 우리는 데이터를 인덱스의 도움 없이 찾기를 한다면 400만 권 책을 싹 다 뒤져서 아이유를 찾는 것이다. 생각만 해도 무시무시하다.

하지만 인덱스를 사용하면 책의 찾아보기만 보고 아이유를 찾는 것이다. 시간이 무척이나 단축이 된다.

### 인덱스 생성

```smalltalk
create index idx_member_name
on member(member_name);
```

### 뷰란

가상의 테이블이라고 할 수 있다. 뷰는 실제 데이터가 없다. 바탕화면의 바로가기 버튼이라고 생각하면 된다. 바탕화면에 크롬 바로가기 아이콘이 있다. 그러면 바탕화면에 크롬이 있는 것이 아니다. 다만 아이콘과 실제로 다른 장소에 있는 파일이 연결되어 바로가기 아이콘을 실행하면 파일이 켜지도록 연결되어 있는 시스템이다.

사용자가 아이유를 찾기 위해서 뷰에 접근하면 뷰에서 실제테이블을 가지고 와서 보여주는 것이다. 또한 뷰의 실체는 테이블을 select하게 하는 구문으로 되어있다.

이렇게 진행되면 사용자는 본인은 뷰에 접근했지만 테이블에 접근한 것 같은 착각을 할 수 있게 된다.

### 뷰 생성

```smalltalk
create view member_view
As
select * from member_view;
```

나중에 더 자세하게 배운다.

### 스토어드프로시저

아주 쉽게 설명하면 MySQL에서 반복문을 사용할 수 있게 해주는 것이다. 이 것의 개념은 매우 어려움으로 나중에 다시 정리해보겠다.

### 스토어드프로시저 생성

```smalltalk
Delimiter //
create procedure myproc()
begin
select * from member where member_name = '나훈아';
select* from products where product_name= '삼각김밥';
end //
Delimiter ;
```

여기서 myproc은 본인 원하는 단어로 바꿔도 상관없다.

```smalltalk
call myproc();
```

이제 이 문장으로

```smalltalk
select * from member where member_name = '나훈아';
select* from products where product_name= '삼각김밥';
```

이 문장과 같은 효과를 받을 수 있다.
