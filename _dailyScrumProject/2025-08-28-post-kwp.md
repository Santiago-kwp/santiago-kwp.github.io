## [OS] Lecture4. Thread Management
### 순 공부 시간

8.28.22:40 ~ 23:45 (65분)

### 학습 목표 : 운영체제의 스레드에 대한 개념적 이해, 스레드 관리란 무엇인가?

### 학습 내용 요약

- 스레드란 프로세스가 받은 자원은 공유를 하지만, 각각의 스레드마다 제어 요소를 가진다(프로그램 카운터, 스택 포이터, 스택(지역 데이터) 등)
- 스레드를 통해 한 프로세스에서 여러 작업을 할 수 있으며, 커널의 개입이 없어 문맥 교환이 없어지므로 자원 효율적이다. 또한 병렬 처리가 가능하다.
- 스레드는 사용자 수준 스레드와 커널 수준 스레드로 분류할 수 있으며, 각각 사용자 수준 스레드 : 커널 수준 스레드의 비율로 구분한다면 전자는 1 대 다 맵핑, 후자는 1대 1맵핑이다.
  - 사용자 수준 스레드는 라이브러리를 통해 구현되어 문맥 교환에 대한 오버헤드가 없으며, 이식성이 높고 유연한 장점을 가지나 하나의 커널 스레드에 맵핑되므로, 여러 스레드 중 block상태가 되는 스레드가 하나 있으면 나머지 스레드도 다 block이 된다.
  - 반면에, 커널 수준 스레드는 여러 스레드 중 하나가 block 상태가 되어도 다른 스레드는 영향을 받지 않고 병행 작업이 가능하지만, 커널 수준의 스레드 간 문맥 교환이 일어나므로 오버헤드가 크다.
  - 그래서 혼합형 스레드 모델이 활용되고 있다.

### 프로세스와 스레드

> 목적을 달성하기 위한 연산을 하는데 프로세스는 자원을 할당 받고, 그 자원을 제어해서 목적을 달성하는 것이 프로세스가 하는 일 ⇒ 자원을 할당 받는 일과 , 그 자원을 제어하는 일로 구분한다면 스레드는 그 자원을 제어하는 일에 해당됨.
>

![lec4_processThread.png](/assets/images/lec4_processThread.png)

- 하나의 프로세스 안에 여러 개의 스레드가 존재할 수 있으며, 프로세스가 할당 받은 자원은 공유한다.
  - 자원은 메모리 공간의 힙, 데이터 영역, 코드 영역
- 하나의 스레드에는 제어 정보(스택 포인터, 프로그램 카운터, 상태 등), 지역 데이터, 스택(Stack)이 존재한다.

![lec4_threadMemory.png](/assets/images/lec4_threadMemory.png)

### 스레드

- 경량 프로세스(Light weight process)
- 프로세서(e.g. CPU) 활용의 기본 단위
- 구성 요소
  - 스레드 ID
  - Register set (PC, SP 등)
  - Stack (i.e. local data)
- 제어 요소 (각 스레드의 것) 외 코드, 데이터 및 자원들은 프로세스 내 다른 프로세스들과 공유

### 스레드의 장점

- Resource sharing : 앞서 얘기했던 문맥 교환(context switching)은 매우 비싼 연산인데, 2개 이상의 프로세스가 하나의 자원을 같이 쓰게 되면 문맥 교환이 발생되나, 동일 프로세스 내 2개 이상의 스레드가 하나의 자원을 같이 쓰는 것은 문맥 교환이 발생하지 않으므로, 즉 커널의 개입이 없는 과정이므로 효율적이다.
- 경제성 : 프로세스의 생성, context switch에 비해 효율적
- 멀티 프로세서 활용 : 병렬 처리를 통한 성능 향상
- 사용자 응답성 (Responsiveness) : 일부 스레드가 처리 지연되어도 다른 스레드는 작업을 계속 처리 가능
  - FPS 게임을 예로 들면, 만약에 스레드 하나로 마우스 움직임도 해야 되고, 화면도 봐야 하고, 적의 움직임의 소리도 들어야 한다. 이 모든 과정은 I/O 로 각 기능을 수행하기 위해서 block 상태로 만들었다가, 다시 대기 상태, 자원 할당 등의 문맥 교환이 발생하며 이것들은 다 오버헤드로 게임을 제대로 할 수가 없을 것이다.
  - 스레드가 여러 개로 자원을 공유하여 작업하게 되면 마우스 입출력은 한 스레드가, 모니터 입출력은 또 한 스레드가 각각 담당하면 문맥 교환없이 동시에 처리할 수 있다.

### 스레드의 구현

### 사용자 수준 스레드 (User Thread)

- 사용자 영역의 스레드 라이브러리로 구현됨
  - 스레드의 생성, 스케쥴링 등
  - POSIX threads, Win32 Threads, Java thread API 등
- 스레드 라이브러리로 스레드 제어 블록을 통해 관리
  - 커널 수준 스레드 하나에 여러 개의 사용자 수준 스레드가 맵핑된다.
- 즉, 커널은 스레드의 존재를 모름 ⇒ 생성 및 관리의 부하가 적음. 유연한 관리 기능
  - 이식성 (Portability)이 높음 → 라이브러리만 있으면 우리가 만든 프로그램을 돌릴 수 있다
- 단점 : 커널은 프로세스 단위로 자원 할당 ⇒ 만약, 하나의 스레드가 I/O 요청이 필요하여 block상태가 된다면, 다른 모든 스레드는 I/O가 필요하지 않아도 block 상태로 대기

![lec4_userThread.png](/assets/images/lec4_userThread.png)

### 커널 수준 스레드 (Kernel Threads)

- 단점 : 커널이 스레드를 직접 생성/관리 (1:1 맵핑) ⇒ 오버헤드가 크다!
  - 프로세스의 문맥 교환보다는 비용이 상대적으로 적지만, 스레드 간 커널을 대상으로 문맥 교환이 일어나므로 사용자 수준 스레드에 비해 오버헤드가 크다.
- 장점 : 프로세스 내 스레드들이 병행적으로 수행 가능
  - 하나의 스레드가 block 이 되어도 다른 스레드는 영향을 받지 않는다.

> 그러면 각 방법마다 장단점이 있으니, 사용자 수준 스레드 (1 대 다)와 커널 수준 스레드( 1대 1)을 섞어서 쓰자 ⇒ 다 대 다 모델 : 혼합형 스레드 모델 등장!
>

### 혼합형 스레드

- n 개의 사용자 수준 스레드 - m 개의 커널 수준 스레드 (n ≥ m)
  - 사용자는 원하는 수만큼 스레드 사용
  - 커널 스레드는 자신에게 할당된 사용자 수준 스레드가 block되더라도 다른 사용자 수준 스레드는 영향을 받지 않고 작업 수행이 가능 ⇒ 병행 처리 가능 **(효율적이면서 유연한 구조)**
