# 데이터베이스의 기초

## 학습 내용 요약
- 데이터베이스의 개념과 일상생활에서 분류된 데이터베이스의 종류, 특징과 시스템에 대해 복습

## 데이터베이스

### 1. 데이터베이스란?
- 조직에 필요한 정보를 얻기 위해 논리적으로 연관된 데이터를 전자적으로 저장하고 구조적으로 통합해 놓은 것

### 2. 일상생활의 데이터베이스
- 통합된 데이터(integrated data)
  → 데이터를 통합하는 개념으로, 각자 사용하던 데이터의 중복을 최소화하여 중복으로 인한 데이터 불일치 현상을 제거
- 저장된 데이터(stored data)
  → 문서로 보관된 데이터가 아니라 디스크, 테이프 같은 컴퓨터 저장장치에 저장된 데이터를 의미
- 운영 데이터(operational data)
  → 조직의 목적을 위해 사용되는 데이터를 의미한다. 즉 업무를 위한 검색을 할 목적으로 저장된 데이터
- 공용 데이터(shared data)
  → 공동으로 사용되는 데이터를 의미

### 3. 데이터베이스의 특징
- 실시간 접근성(real time accessibility)
  → 데이터베이스는 실시간으로 서비스, 사용자가 데이터를 요청하면 몇 시간이나 몇 뒤에 결과를 전송하는 것이 아니라 수 초 내에 결과를 서비스
- 계속적인 변화(continuous change)
  → 데이터베이스에 저장된 내용은 어느 한 순간의 상태를 나타내지만, 데이터 값은 시간에 따라 항상 바뀜. 데이터베이스는 삽입(insert), 삭제(delete), 수정(update) 등의 작업을 통하여 바뀐 데이터 값을 저장
- 동시 공유(concurrent sharing)
  → 데이터베이스는 서로 다른 업무 또는 여러 사용자에게 동시에 공유동시(concurrent)는 병행이라고도 하며, 데이터베이스에 접근하는 프로그램이 여러 개 있다는 의미
- 내용에 따른 참조(reference by content)
  → 데이터베이스에 저장된 데이터는 데이터의 물리적인 위치가 아니라 데이터 값에 따라 참조

### 4. 데이터베이스 시스템
- DBMS(데이터베이스 관리 시스템) → DBMS 서버가 파일을 다루며 데이터의 일관성 유지, 복구, 동시 접근 제어 등의 기능을 수행
- 데이터베이스 -> 언어: SQL
- 데이터모델 → RDB(관계형 데이터베이스)로 데이터베이스를 구축

#### SQL (구조화된 질의 언어)
  - DDL (데이터 정의어) - Create, Alter, Drop
  - DML (데이터 조작어) - Insert, Update, Delete
  - DCL (데이터 제어어) - Revoke, Grant
  - DQL (데이터 질의어) - Select
  - TCL (트랜젝처리 언어) - Commit, Rollback

#### 스키마 - 3단계 데이터베이스 구조
스키마: 데이터베이스의 설계도
- 스카마가 필요한 이유
  1. 데이터 구조 정의
  -> 어떤 테이블이 있고, 어떤 컬럼이 있으며, 자료형은 무엇인지 명확히 규정 → 데이터 저장 형식이 통일됨.
  2. 데이터 무결성 보장
  -> Primary key, Foreign key, Not Null, Unique 같은 제약조건을 통해 잘못된 데이터 입력을 방지.
  3. 일관성 유지
  -> 여러 사용자가 동시에 접근해도 같은 규칙을 따르므로 충돌이나 혼란이 줄어듦.
  4. 효율적 관리
  -> 설계도를 기반으로 DBMS가 인덱스, 쿼리 최적화 등을 수행할 수 있음.
  5. 확장성과 유지보수
  -> 스키마를 기준으로 새로운 기능 추가, 테이블 확장, 마이그레이션 등을 체계적으로 할 수 있음.

- 스키마의 종류
  - 외부 스키마 -> 일반 사용자나 응용 프로그래머의 접근 계층, 논리적인 부분을 의미, 여러 외부 스카마가 있을 수 있음, '서브 스키마'라고도 하며 뷰의 개념이다.
  - 개념 스키마 -> 데이터베이스 전체를 의미, 하나만 존재 가능, DBA가 관리한다.
  - 내부 스키마 -> 물리적 저장 장치에 저장되는 방법의 표현, 하나만 존재 가능, 인덱스. 데이터 레코드의 배치 방법 등 관한 사항이 포함한다.
