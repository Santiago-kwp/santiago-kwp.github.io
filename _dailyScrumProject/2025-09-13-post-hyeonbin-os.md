# 1. Spinlock

## Spinlock 개요

- 초기화, `P()` , `V()` 연산으로만 접근 가능한 정수형 변수
    - 정수형 변수 `S`  사용
        - 현재 임계 영역에 진입 가능한 프로세스의 개수
        - lock 역할도 수행
    - H/W에서는 1개의 TAS 연산에 관해서만 실행 시의 원자성을 보장했다면, Spinlock lock 설정/해제의 2개 연산에서는에 관해 실행 시의 원자성을 보장하도록 개선
- Spinlock에서의 초기화, `P()` , `V()` 연산은 원자성을 지닌 연산

cf.1) 원자성(atomic) = All or Nothing

- 단일 명령어(instruction)를 1개의 명령어 사이클에서 처리하여 중간 결과의 노출 없이 실행이 완료되거나, 아예 실행되지 않는 것만 가능한 성질
- 단일 연산이 여러 개의 명령어로 구성되어 있을 때, 해당 명령어들을 1개의 단위로 취급하여 중간 결과를 노출시키지 않는 것

cf.2) 명령어 사이클(instruction cycle)

- CPU가 메모리에서 읽어온 명령어를 실행할 때마다 수행하는 일련의 과정
- Fetch(명령어 인출) → Decode(명령어 해석) → Execute(명령어 실행)

## Spinlock의 주요 연산

- 초기화 연산
    - 정수형 변수 `S`의 값을 양수로 초기화
- `P()` 연산(Probern → 검사 연산)
    - 변수 `S`의 값을 검사하여 lock이 걸려 있는지를 검사하는 연산
    - lock이 걸려 있지 않다면, 현재 프로세스가 임계 영역에 관한 lock을 건 다음 임계 영역으로 진입하는 연산
    - **“Spin”lock**이란 명칭은 한 프로세스가 임계 영역에 진입하여 lock이 걸렸을 때, 대기 중인 다른 프로세스에서는 while문을 돌면서 lock이 풀렸는지를 계속 확인하는 것에서 비롯됨
    
    ```java
    // 정수형 변수 S는 Spinlock을 의미
    P(S) {
    	// Spinlock을 걸어둔 다른 프로세스가 있으면 대기
    	// (이 부분에서 busy waiting 발생)
    	while(S <= 0) {
    	}
    	// 임계 영역으로 진입하면서 잠금
    	S = S-1;
    }
    ```
    
- `V()` 연산(Verhogen → 증가 연산)
    - 프로세스가 임계 영역에서의 작업을 종료할 때, 걸어둔 lock을 해제하기 위해 변수 `S`의 값을 증가시키는 연산
    
    ```java
    V(S) {
    	// 임계 영역을 빠져나오면서 잠금 해제
    	S = S+1;
    }
    ```
    
- `P()`, `V()` 연산 수행 과정에서 값이 변동되면서 lock 설정/해제

## Spinlock의 장점

- H/W에서의 상호배제 방법보다 구현 코드가 더욱 단순해짐
    - 즉, S/W의 상호배제 알고리즘
    → H/W에서의 TAS 명령어를 적용한 알고리즘
    → OS의 Spinlock 
    순으로 상호 배제 적용 방법이 개선됨

## Spinlock의 단점

- 멀티 프로세서에서만 사용 가능
    - 싱글 프로세서에서는 한번에 1개 프로세스만 실행 가능하고, `P()` 연산은 `V()` 연산을 별도로 실행하지 않는 한 실행 시 원자성을 보장받으므로, `P()` 연산을 중단시킬 방법이 없기 때문
- 여전한 busy-waiting 문제
    - 프로세스의 대기 상태를 유지하기 위해 while문의 무한루프를 사용한다는 점에서는 벗어나지 못함
    (따라서, while문에 의한 오버헤드는 여전히 존재)

# 2. Semaphore

## Semaphore 개요

- Spinlock의 busy-waiting 문제를 해결하기 위해 도입된 상호 배제 방식
- 세마포어 변수 `S` 사용
    - 초기화 연산, `P()` , `V()` 연산으로만 접근 가능한 정수형 변수
    - `unsigned int` 타입을 사용한다는 차이가 있을 뿐, 기본적인 의미와 역할은 Spinlock과 유사
    - 하지만, while문을 사용하는 대신 임의의 **변수 S마다 Ready Queue를 할당**한다는 점이 다름

## Semaphore의 종류

**Binary Semaphore**

- `S`에는 0과 1만 보유할 수 있음
- 상호배제 및 프로세스 동기화에 사용됨

**Counting Semaphore**

- `S` 가 0 이상의 정수값을 보유할 수 있음
- 생산자-소비자 문제 등을 해결하기 위해 사용됨

## Semaphore의 주요 연산

- 초기화 연산 → 변수 `S`의 초기값을 부여
- `P()` 연산(Probern → 검사 연산)
    - 프로세스가 임계 영역에 진입 가능한지를 검사
    - `S` 값이 0보다 커서 임계 영역에 진입 가능하면 `S` 값이 1 감소
    - `S` 값이 0이 되어 임계 영역에 진입할 수 없다면, 현재 프로세스는 Ready Queue로 이동하여 대기
- `V()` 연산(Verhogen → 증가 연산)
    - 현재 Ready Queue가 비어 있지 않다면, 큐에서 대기 중인 프로세스를 꺼내서 실행
    - Ready Queue가 비어 있다면 `S` 값은 1 증가

## Semaphore의 활용

### 상호배제 문제

![lec16_mutex.png](/assets/images/lec16_mutex.png)

- Binary Semaphore를 사용
- 프로세스가 임계 영역으로 진입하기 전 `P()` 연산 수행
    - 임계 영역에 진입 가능하면 lock을 설정하고 진입
    - 임계 영역에 진입 불가능하면 **while문을 반복하는 대신 Ready Queue에서 대기**
- 임계 영역에서의 작업을 완료한 프로세스는 `V()` 연산을 실행하여 걸어둔 lock을 해제

### 프로세스 동기화 문제

- `P()` 연산을 실행한 프로세스는 이미 임계 영역에 진입한 다른 프로세스가 `V()` 연산을 실행할 때까지 대기하는 방식으로 프로세스 간 실행 순서를 조율
- 위 작업을 수행하기 위해, 세마포어 변수 `S`의 증감이 이루어짐

### 생산자-소비자 문제

- **생산자-소비자 관계**
    - 생산자: 메시지를 생성하는 프로세스 그룹
    - 소비자: 메시지를 전달받는 프로세스 그룹
    - 생산자가 공유 메모리 버퍼에 메시지를 저장(→ 생산)하면 소비자가 해당 버퍼에서 메시지를 읽어오는(→ 소비) 관계
- **생산자-소비자 문제(Producer-Consumer Problem)**
    - 아래의 2가지 문제를 모두 지칭
        - 생산자 프로세스가 공유 버퍼에 데이터를 저장하기도 전에, 소비자 프로세스가 공유 버퍼에 접근하는 문제
        - 여러 개의 생산자 프로세스가 동시에 공유 버퍼에 데이터를 저장하려 할 때, 데이터 저장 순서에 따라 최종적인 저장 결과가 달라지는 문제
- **Semaphore를 활용한 해결법 - 1개의 공유 버퍼**
    
    ![lec16_pcproblem_1.png](/assets/images/lec16_pcproblem_1.png)
    
    - 2개의 세마포어 변수 `produced`, `consumed` 를 사용하여 각각의 변수에 관한 `P()`, `V()` 연산을 수행하는 방식
        - Binary Semaphore 사용
        - `produced`와 `consumed` 는 항상 서로 다른 값을 보유
    - 생산자-소비자 또는 생산자-생산자 사이에서 공유 버퍼에 진입하는 순서를 조율
- **Semaphore를 활용한 해결법 - N개의 공유 버퍼**
    
    ![lec16_pcproblem_2.png](/assets/images/lec16_pcproblem_2.png)
    
    - 생산자-소비자가 M:N 관계일 때, 공유 버퍼로의 접근은 각각 1개씩의 생산자와 소비자 프로세스만 수행할 수 있도록 실행 순서를 조정
    - 4가지의 세마포어 변수를 사용
        - 각각의 변수는 생산자, 소비자, 사용 중인 버퍼, 유휴 상태인 버퍼의 개수를 의미
        - (사용 중인 버퍼 수)+(유휴 상태인 버퍼 수) = (공유 버퍼의 총 개수)
    - 2가지 종류의 `P()` - `V()` 연산 쌍을 아래의 용도대로 사용
        - 임계 영역에 해당하는 공유 버퍼에 관한 lock 설정/해제
        → 생산자-소비자 간 공유버퍼 진입 순서 조율
        - 생산자-생산자, 소비자-소비자 간 임계 영역 진입 순서 조율

### Reader-Writer 문제

- **Reader-Writer 관계**
    - Reader: 데이터 조회 연산만 수행하는 프로세스
    - Writer: 데이터 변경(추가, 수정, 삭제) 연산을 수행하는 프로세스
- **Reader-Writer 문제**
    - Reader들끼리는 동일한 데이터에 동시에 접근해도 데이터의 무결성을 보장할 수 있음
    - 동시에 데이터에 접근하는 프로세스들 중 **Writer 프로세스가 1개라도 포함된 경우, 임계 영역에 진입하는 순서에 따라 결과가 달라지면서 데이터 무결성을 위배하게 되는 문제**
    - Reader나 Writer에게 임계 영역 데이터에 관한 우선권을 부여
        - Reader 우선 → Reader가 임계 영역 점유 시, Writer는 대기
        - Writer 우선 → Writer가 임계영역 점유 시, Reader는 대기
- **Semaphore를 활용한 해결법 - Reader 우선**
    
    ![lec16_reader_first.png](/assets/images/lec16_reader_first.png)
    
    - Reader 프로세스에서는 데이터 조회에 관한 사전/사후 단계에서 Semaphore를 활용한 상호 배제 수행
        - 사전 준비 단계에서는 Writer 프로세스를 대상으로 lock을 설정하고, 사후 처리 단계에서 해당 lock을 해제
        - 여러 개의 Reader 프로세스를 사용할 경우, 동일한 Writer 프로세스에 대해 lock 설정/해제를 모두 1번씩만 수행하도록 처리할 때도 Semaphore 연산을 사용
    - Writer 프로세스에서는 Reader-Writer, Writer-Writer 간 데이터 접근 순서를 조정하는 용도로만 사용
- **Semaphore를 활용한 해결법 - Writer 우선**
    - Reader를 우선적으로 실행할 때와 같은 방식으로, Writer의 데이터 갱신 작업을 기준으로 사전/사후 단계에서 Semaphore를 활용한 동기화 처리를 수행

## Semaphore의 장단점

- busy-waiting 문제를 해결
    - Ready Queue를 사용하여 대기 중인 프로세스를 block하는 방식을 사용
    - while문으로 인한 오버헤드 문제를 해결
- 하지만, 대기 중인 프로세스를 다시 실행시키는 순서는 무작위
    - 상황에 따라서는 기아 문제가 발생할 수 있음
    - 이 문제를 해결하기 위해, EventCount와 Sequencer를 활용

# 3. Eventcount와 Sequencer

## Sequencer

### Sequencer 변수

- 은행에서 뽑은 번호표에 부여된 순번에 해당
- 정수형 변수 `S` (Sequencer)
    - 0 이상의 정수값을 사용하며, 생성 시 0으로 초기화
    - 한번 증가하면 감소하지 않으므로, **실행하려는 프로세스들에게 순번을 부여할 때** 활용됨
    - `ticket()` 연산으로만 접근 및 변경 가능

### Sequencer의 주요 연산

- `ticket(S)` 연산
    - 현재 프로세스에게 순번을 부여하는 연산
    - 현재까지 `ticket()`이 호출된 횟수를 반환하면서 다음 순번을 부여하기 위해 `S` 값을 1 증가시키는 연산

## Eventcount

### Eventcount 변수

- 은행 창구에서 업무를 처리한 횟수에 해당
- 0 이상의 정수값을 갖는 정수형 변수 `E` 로 표현
    - 생성 시 0으로 초기화되며, 한번 증가하면 다시 감소하지 않음
    - **현재까지 프로세스들이 특정 작업을 수행한 횟수**를 의미하며, 프로세스의 대기/실행 여부를 결정하는 기준으로 활용됨
    - `read(E)`, `advance(E)`, `await(E, v)` 연산으로만 접근

### Eventcount의 주요 연산

`read(E)` 연산

- 현재 `E`의 값을 반환하는 연산

`advance(E)` 연산

- 현재 `E`의 값을 1 증가시키고, 대기 중인 프로세스들 중 이렇게 증가된 `E`와 순번이 동일한 프로세스를 실행시키는 연산

`await(E, v)` 연산

- `v`는 현재 프로세스에게 부여된 순번에 해당
- 변수 `E`가 `v`보다 작다면 아직은 실행할 차례가 아닌 것으로 취급하여 현재 프로세스를 대기시키고, 크다면 현재 프로세스를 그대로 실행
- 현재 프로세스가 대기 중일 때는 `E`에 관한 Ready Queue로 이동

## Eventcount/Sequence의 활용

### 상호 배제 문제

![lec17_eventcount_mutex.png](/assets/images/lec17_eventcount_mutex.png)

- `P()` 연산을 구현하기 위해 `ticket()` 과 `await()`를 사용
    - 프로세스는 임계 영역에 진입하기 전 `ticket()` 을 통해 순번을 부여받는데, 이는 해당 프로세스가 Ready Queue에서 대기하고 있다가 재실행될 때도 순서대로 진행됨을 의미
    - 임계 영역에 진입하기 전에 `await()`를 호출했을 때, 현재 프로세스가 임계 영역에 진입할 차례가 아니면 대기
- `V()` 연산을 구현하기 위해 `advance()` 사용
    - 프로세스가 임계영역을 벗어나면 `advance()`를 호출하여 `E`를 증가시켜 다음에 임계 영역에 진입할 프로세스의 실행을 준비

### 생산자-소비자 문제

![lec17_pcproblem.png](/assets/images/lec17_pcproblem.png)

- 생산자, 소비자 각각의 순번을 의미하는 Sequencer 변수 사용
    - `Pticket`(생산자), `Cticket`(소비자)의 2가지
- 생산자, 소비자의 공유버퍼 접근 횟수를 나타내는 Eventcount 변수 사용
    - `in`(생산자 → 공유버퍼),  `out`(소비자 → 공유버퍼) 의 2가지 사용
- Eventcount의 연산들을 활용하여 `P()` 연산과 `V()` 연산을 구현하고, 다음의 작업을 수행할 때 상호배제를 적용하여 프로세스 간 실행 순서를 조율
    - 생산자들 간 임계 영역 진입 순서 조정
    - 소비자들 간 임계 영역 진입 순서 조정
    - 생산자-소비자 간 공유 버퍼 접근 순서 조정

## Eventcount/Sequence에서 개선된 사항

- busy-waiting 문제 해결
    - 프로세스를 대기시킬 때, while문을 반복하는 대신 Ready Queue에 프로세스를 추가하는 방식을 사용
    - while문 반복으로 인한 오버헤드가 발생하지 않음
- 대기 중인 프로세스 재실행 시 기아 문제 해결
    - FIFO 방식 → Ready Queue에 추가된 순서대로 재실행
- 프로세스 실행 순서를 더욱 세밀하게 조정 가능
