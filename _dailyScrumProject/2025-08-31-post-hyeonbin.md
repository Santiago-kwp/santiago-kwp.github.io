## 1. 스레드의 개념
### 프로세스(Process)
- 리소스의 할당 및 제어를 모두 담당하는 프로그램 실행의 흐름
  - 실행에 필요한 리소스는 프로세스 단위로 할당됨 -> CPU, 메모리(스택 영역 이외의 나머지)
  - 할당받은 리소스의 제어는 프로세스 내부의 스레드 단위로 수행

### 스레드(Thread)
**개요**
- 프로세스 내부의 개별적인 리소스 제어 흐름
- 프로세스에 포함된 스레드들은 할당받은 리소스를 공유하지만, 리소스 제어는 개별적으로 수행
  - 제어에 사용되는 리소스들만 스레드마다 할당받아 사용
  - 제어만을 담당하므로, 프로세스보다 작은 실행 흐름 -> 경량화 프로세스(Lightweight Process)라고도 불림
  - CPU 활용의 기본 단위 -> 스레드 1개당 1개의 CPU 코어를 사용, 멀티코어라면 멀티스레딩 가능

**스레드의 구성 요소**
- 프로그램 실행을 제어하기 위한 요소들은 개별 스레드마다 보유
- 스레드의 주요 구성 요소
  - 스레드 ID
  - 프로그램 카운터(PC), 스택 포인터 등의 제어 정보
  - 스택 영역: 지역변수 및 호출할 메서드 정보를 저장


### 싱글스레드와 멀티스레드
- 싱글스레드: 프로세스 내부에 1개의 스레드만 존재
- 멀티스레드: 프로세스 내부에 여러 개의 스레드가 존재


### 스레드의 장점
**사용자 응답성**
- 일부 스레드의 처리가 지연되더라도, 다른 스레드에서의 작업은 그대로 진행 가능
- 동일한 자원을 공유하면서도 여러 가지 작업을 수행할 수 있음

**자원 공유 & 경제성**
- 자원을 공유하여 효율성이 증가
- 여러 개의 스레드가 동일한 프로세스에 존재 -> 동일한 PCB를 공유하므로, 컨텍스트 스위칭이 발생하지 않음
- 따라서, 컨텍스트 스위칭으로 인한 추가비용이 발생하지 않음

**멀티 프로세서 활용(Multi-Processor)**
- 1개의 스레드당 1개의 CPU 코어를 점유
- 멀티코어(= 멀티프로세서)를 활용하여 병렬 처리 성능을 개선하는 것이 가능

## 2. 스레드의 구현 
### 사용자 수준 스레드(User Thread)
- 사용자 영역에서 제공하는 스레드 라이브러리를 통해 구현되는 스레드
- 일반적으로 여러 개의 스레드를 사용 -> n개의 사용자 스레드는 1개의 CPU를 공유
- 커널의 직접적인 개입을 받지 않음
  - 동일 프로세스 내 다른 스레드와 리소스를 공유하여, 생성 및 관리비용이 적음
  - 제공되는 스레드 라이브러리가 동일하다면, 프로그램을 다른 시스템에서 사용 가능

### 커널 수준 스레드(Kernel Thread)
- 운영체제의 커널이 직접 관리하는 스레드
  - 커널은 각 스레드를 개별적으로 관리 -> 각각의 스레드를 병렬적으로 실행 가능
- 커널 영역에서의 스레드 생성 및 관리를 담당 -> 컨텍스트 스위칭으로 인한 추가비용 증가
- 사용자 스레드와는 1:1 관계
  - 1개의 커널 스레드에게는 1개의 사용자 스레드를 할당

### 혼합형 스레드
- 사용자 수준 스레드와 커널 수준 스레드의 장점을 합친 스레드
- n개의 사용자 수준 스레드와 m개의 커널 수준 스레드를 사용
  - 사용자는 원하는 만큼 스레드를 사용할 수 있음
  - 커널 스레드에 할당된 사용자 스레드의 작업이 지연되어도 여분의 사용자 스레드를 사용할 수 있음
  - 따라서, 효율적이고 유연함
