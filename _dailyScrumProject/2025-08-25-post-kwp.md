### 학습 내용 요약

- 운영체제는 하드웨어를 관리, 운영하여 사용자에게 하드웨어 및 소프트웨어를 활용할 수 있게 하는 역할을 담당
- 운영체제는 커널, 시스템 콜을 포함하며, 시스템 콜은 사용자가 직접 커널을 제어하지 않고, 하드웨어를 제어하기 위해 커널에 요청하는 통로를 제공함
- 운영체제의 구분은 작업 수행 방식에 따라 일괄 처리, 시분할 시스템, 분산 처리 시스템, 실시간 시스템으로 구분됨
- 운영체제는 커널 + 시스템 콜 + 유틸리티로 구성되며, 단일 구조, 계층 구조, 마이크로 커널 구조가 있음
- 운영체제는 컴퓨터의 모든 자원의 관리를 담당한다고 할 수 있음 : 프로세서, 프로세스, 메모리, 입출력, 기타 보조 장치 등등

### 운영 체제의 역할

- User Interface (편리성)
  - CUI, GUI, EUCI (End User Comfortable Interface)
- Resource management (효율성)
  - H/W Resource
  - S/W Resource
- Process and Thread management
  - Process : 실행의 주체
  - Thread : 실행 흐름의 단위
- System management (시스템의 보호)

### 운영체제의 구분

- 동시 사용자수
  - Single-user System
    - Windows, Android, IOS, …
    - 한 명의 사용자가 모든 시스템 자원을 독점
    - 자원 관리 및 시스템 보호 방식이 간단함
  - Multi-user System
    - Linux, Unix, Windows Server, …
    - 각종 시스템 자원(파일 등)에 대한 소유 권한 관리가 필요
    - 기본적으로 멀티 태스킹 기능이 필요
    - OS의 기능 및 구조가 복잡함
- 동시 실행 프로세스 수
  - 단일 작업 (Single-tasking system)
    - 시스템 내에 하나의 작업(프로세스)만 존재
    - 운영체제 구조가 간단
    - MS-DOS
  - 다중 작업 (Multi-tasking system)
    - 동시에 여러 작업(프로세스)의 수행 가능
      - 작업들 사이의 동시 수행, 동기화 등을 관리해야 함.
    - 운영체제의 기능 및 구조가 복잡
- 작업 수행 방식
  - 순차 처리( ~ 1940, 천공카드)
    - 운영체제 개념 없음
    - 실행하는 작업 별 순차 처리 - 각각의 작업에 대한 준비 시간 필요
  - 배치 시스템(Batch System, 1950 ~ 1960)
    - 일괄처리 시스템으로 사용자의 요청 작업(천공카드 등)을 일정 시간 모아두었다가 한번에 처리
    - 시스템 지향적(system oriented)
      - 많은 사용자가 시스템 자원 공유
      - 처리 효율 향상
    - 개인적 입장에서 생산성 저하
      - 같은 유형의 작업들이 모이기를 기다려야 함
      - 긴 응답시간 (작업 제출부터 결과를 받기까지)
  - 시분할 시스템(Time sharing system, 1960 ~ 1970)
    - 시간을 쪼개서 여러 프로세스가 사용하는 시스템
    - 여러 사용자가 자원을 동시에 사용
      - OS가 파일 시스템 및 가상 메모리 관리
    - 사용자 지향적(User-oriented)
      - 대화형 시스템
    - 장점
      - 응답시간(response time) 단축
      - 생산성 향상
        - 프로세서 유휴 시간 감소
    - 단점
      - 통신 비용 증가
        - 통신선 비용, 보안 문제
      - 개인 사용자 체감 속도 저하
        - 동시 사용자 수 증가 → 시스템 부하 증가 → 느려짐(개인적인 관점)
  - Personal Computing
    - CPU의 사용률보다는 사용자 편의가 중요함
    - OS가 비교적 단순하지만, 다양한 사용자 지원 기능 탑재
    - 빠른 응답시간, 낮은 성능
  - Parallel Processing System
    - 하나의 시스템에 여러 개의 CPU를 쓰자
    - 메모리 등의 자원 공유
      - CPU는 여러 개인데 기타 자원은 공유(Tightly coupled system)
    - 사용 목적 : 성능 향상, 신뢰성 향상(하나가 고장 나도 정상 동작 가능)
  - Distributed Processing System
    - 분산 처리 시스템으로 네트워크를 통해서 구축된 병렬처리 시스템 (Loosely-coupled system)
    - 사용자는 분산 운영체제를 통해 하나의 프로그램, 자원처럼 사용 가능
    - Cluster system, Server - client system, P2P
    - 장점
      - 자원 공유를 통한 높은 성능
      - 고신뢰성, 고확장성
    - 단점
      - 구축 및 관리가 어려움
  - Real-time System (실시간 시스템)
    - 작업 처리에 시간 제한(데드라인)을 가지는 시스템
      - 제한 시간 내에 서비스를 제공하는 것이 자원 효율보다 중요한
    - 작업의 종류
      - Hard Real-time task : 발전소, 무기 제어 등
      - Soft Real-time task : 동영상 스트리밍
      -

### 운영체제의 구조

> 운영체제는 커널과 유틸리티로 구성됨. ⇒ 하드웨어 ⇒ 커널 ⇒ 시스템 콜 ⇒ 유틸리티 ⇒ 응용 소프트웨어
>
- 커널(Kernel)
  - OS의 핵심 부분 (메모리 상주)
  - 가장 빈번하게 사용되는 기능들 담당 : 프로세서 및 메모리 관리 등
- 유틸리티
  - 비상주 프로그램
  - UI 등 서비스 프로그램

운영체제 구조의 종류

- 단일 구조
  - 커널 내 모듈 간 직접 통신 ⇒ 효율적 자원 관리 및 사용
  - 커널의 거대화 ⇒ 오류 및 버그, 추가 기능 구현 등 유지 보수가 어려움
    - 동일 메모리에 모든 기능이 있어, 한 모듈의 문제가 전체 시스템에 영향(예, 악성 코드 등)
- 계층 구조
  - 모듈화 ⇒ 계층 간 검증 및 수정 용의
    - 설계 및 구현 단순화
  - 단점은 단일 구조 대비 성능 저하 ⇒ 원하는 기능 수행을 위해 많은 단계를 거쳐야 되므로
- 마이크로 커널 구조
  - 커널에 필수 기능만 포함시키는 구조

### 운영체제의 기능

> 죄다 관리, 관리, 관리 모든 것을 관리하는 애
>
- 프로세스 관리
  - 프로세스 : 커널에 등록된 실행 단위 (실행 중인 프로그램)
    - 사용자 요청/프로그램의 수행 주체 (entity)
  - 프로세스 관리 기능
    - 생성/삭제, 상태 관리
    - 자원 할당
    - 프로세스 간 통신 및 동기화
    - 교착 상태 해결
  - 프로세스 정보 관리 : PCB(Process Control Block)
- 프로세서 관리
  - 프로세스 스케쥴링
  - 프로세스들에 대한 프로세서 할당 관리
- 메모리 관리
  - 프로세스에 대한 메모리 할당 및 회수
  - 메모리 여유 공간 관리
  - 각 프로세스의 할당 메모리 영역 접근 보호
  - 메모리 할당 방법 조율
- 파일 관리
  - 파일 : 논리적 데이터 저장 단위
- 입출력 관리
  - 입출력은 반드시 운영체제를 거쳐야 한다
- 보조 기억 장치 관리
- 기타 주변 장치 관리
