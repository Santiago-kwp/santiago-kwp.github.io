## [OS] Lecture5. Process Management (1/5)

### 순 공부 시간
25.8.29. 금 21: 30 ~ 21:51 (21분), 22:48 ~ 23:30 (42분)

### 학습 목표 : 프로세스 스케줄링의 정의 및 왜 하는가? 에 대한 이해, 스케쥴링의 기준 및 단계 구분에 대한 개념 이해

### 학습 내용 요약

- 스케쥴링은 시스템의 성능 향상을 목적으로 함! 하지만 성능 향상이란 여러가지 성능 지표가 존재함.
    - 시간 내 프로세스 처리 수, 시간 내 자원 활용 시간 비율, 빠른 응답 시간이 될 수 도 있음
    - 특정한 목적에 따라 성능 지표를 최대화 하는 것이 스케쥴링의 목적임
- 스케쥴링의 기준은 프로세스의 특성에 따라 즉, 계산이 많냐? I/O가 많냐? 일괄 처리 시스템이냐 사용자와 상호작용 시스템이냐? 프로세스가 얼마나 처리가 급한지? 우선순위는 어떤지? 총 실행 시간이 얼마나 긴지에 따라 스케쥴링 해야 한다.
- 스케쥴의 단계는 롱텀 (= 커널에 프로세스 등록), 미드텀 (= 프로세스를 메모리에 할당 ~ swap-in/out, resume), 숏텀 (=프로세스를 프로세서에 할당, ready to running)으로 구분할 수 있다.

### 다중 프로그래밍

- 여러 개의 프로세스가 시스템에 존재해야 함
- 자원을 할당 할 프로세스를 선택 해야 함 ⇒ 시스템 전체의 성능을 높이기 위해서!
- 자원 관리
    - 시간 분할 (time-sharing) 관리
        - 하나의 자원을 여러 스레드들이 번갈아 가며 사용 → cpu (프로세서)
        - 프로세스 스케쥴링 ⇒ 프로세서 사용 시간을 프로세스들에게 분배
    - 공간 분할 (space sharing) 관리
        - 하나의 자원을 분할하려 관리 ⇒ 메모리

### 스케쥴링의 목적

- 시스템의 성능 (performace) 향상
- 대표적 시스템 성능 지표(index)
    - 응답 시간 (response time)
        - 작업 요청(submission)으로부터 얼마나 빠르게  응답을 받았는가
    - 작업 처리량 (throughput)
        - 단위 시간 동안 완료한 작업의 수
    - 자원 활용도 (resource utilization)
        - 주어진 시간 동안 자원이 활용된 시간
- 목적에 맞는 성능 지표를 고려하여 프로세스 스케쥴링을 하여야 한다
    - 응답 시간이 중요한 시스템은 사용자 대화형 시스템, real time system(제한된 시간 내에 반드시 응답)
    - 작업 처리량은 일괄 처리 시스템에서 중요함
    - 자원 활용도는 비싼 자원을 구매했다면 놀리지 않고 열심히 써야…

### 대기 시간, 응답 시간, 실행 시간, 반환 시간

![lec5_processTimeDivision.png](/assets/images/lec5_processTimeDivision.png)

- 대기 시간 (Waiting) : 프로세스가 실행하기 위해 도착한 시간부터 실제 실행 시작 시간까지
- 응답 시간 (Response) : 프로세스가 실행하기 위해 도착한 시간부터 첫 번째 출력, 즉 응답을 한 시간까지
- 실행 시간 (Burst) : 프로세스가 실제 실행 시작한 시간부터 프로세스 종료 시간까지
- 반환 시간 (Turn-around) : 대기 시간 + 실행 시간

### 스케쥴링의 기준 및 단계

> 어떤 기준으로 프로세스를 스케쥴링할까? 우리는 보통 일의 우선순위를 생각해서 중요한 일을 먼저 처리하고, 어렵지만 중요한 일은 그 다음, 어렵지만 중요하지 않은 일은 그 다음, 쉽지만 중요하지 않은 일은 마지막에 시간이 진짜 남으면 처리한다. 이렇듯 스케쥴러도 특정 기준에 따라 스케쥴링하겠지?
>
- 프로세스의 특성 : I/O 에 많은 비중을 차지 하느냐(I/O bounded), 계산에 많은 비중을 차지하느냐 (Compute bounded)
- 시스템 특성 : Batch system or interactive 시스템이냐
- 프로세스의 긴급성 (Urgency)
- 프로세스의 우선순위 (Priority)
- 프로세스 총 실행 시간 (Total service time)

### CPU burst vs I/O burst

- cpu burst : cpu 사용 시간
- I/o burst : I/O 대기 시간

### 스케쥴링의 단계

발생하는 빈도를 기준으로

- long term scheduling
- mid term scheduling
- short term scheduling

### Long term scheduling

- Job scheduling
    - 시스템에 제출할(커널에 등록할 ) 작업(job) 결정
- 다중 프로그래밍 정도 조절
    - 시스템 내 프로세스 수 조절
- I/O bounded와 Compute bounded 프로세스들을 잘 섞어서 선택해야 함
    - 왜냐면 하나에 치중되면 하나가 놀기 때문에 비효율적임

### Mid term scheduling

- 메모리 할당 결정(memory allocation)
- Suspended ready ⇒ ready (swapping : swap - in(=resume) / swap - out)
    - 메모리 할당 유무에 따라서

### Short term scheduling

- process scheduling
    - 프로세서를 할당할 프로세스를 결정 : processor scheduler, dispatcher
- 가장 빈번하게 발생
    - Interrupt, block (I/O), time-out, etc ..
    - 매우 빨라야 함.
      ⇒ CPU 로 100초 걸리는 작업인데, 스케쥴링 결정까지 10초가 걸린다면? 10초만큼 오버헤드
