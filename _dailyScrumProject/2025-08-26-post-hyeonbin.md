## 1. 프로세스의 개념

### 작업과 프로세스
**작업(Job)**
- 실행할 프로그램과, 그 프로그램이 처리할 데이터를 모두 지칭
- 컴퓨터 시스템의 보조기억장치에 저장되어, 아직 주기억장치로 로드되지 않은 프로그램을 의미

**프로세스(Process)**
- 실행 중인 프로그램
  - 실행을 위해 시스템의 커널에 등록된 작업
  - 시스템 커널 영역에서 PCB(프로세스 관리 블록)을 할당받은 개체
- 운영체제는 프로세스를 효율적으로 관리함으로써 컴퓨터 시스템의 성능을 개선할 수 있음

**프로세스의 종류**
- 역할에 따른 분류
  - 시스템(커널) 프로세스: 시스템 메모리/프로세서에 접근하여 커널의 기능을 수행하고 사용자 프로세스를 생성
  - 사용자 프로세스: 사용자가 작성한 코드를 실행
- 병행 수행 방법에 따른 분류
  - 독립 프로세스: 다른 프로세스와의 상호작용 없이 작업을 수행
  - 협력 프로세스: 다른 프로세스와의 상호작용이 발생

## 2. PCB(프로세스 관리 블록)

**PCB 개요**
- 운영체제가 프로세스를 제어하기 위해 필요로 하는 상태정보가 저장된 메모리 공간
- 프로세스 시작 시 커널 영역에 생성되어, 종료 시 소멸됨
(즉, PCB는 프로세스의 생명주기를 결정)
- PCB 참조 및 갱신 속도는 운영체제의 성능을 결정

**PCB가 관리하는 정보**
- 프로세스 ID(= PID): 프로세스를 식별하기 위한 고유 번호
- 스케줄링 정보: 스케줄링 시 우선순위 등의 정보
- 프로세스 상태: 자원 할당 양상, 요청한 자원 등의 상태 정보
- 메모리 관리 관련 정보
- 입출력 상태 정보
- 컨텍스트 저장 영역: 프로세스 중단 시점에 CPU 레지스터에 저장된 데이터
- 계정 정보: 다중 사용자 시스템 등에서 프로세스를 사용하는 계정을 식별

주의) PCB에서 제공하는 정보는 운영체제마다 다를 수 있음

## 3. 프로세스의 상태 변화

### 프로세스의 상태 변화 개요
**자원(Resource)**
- 커널의 관리 하에 프로세스에게 할당/반납되는 수동적인 개체
  (자원 자체는 컴퓨터 시스템에서 별도의 작업을 수행하지 않음)
- 하드웨어 리소스와 소프트웨어 리소스로 세분됨

**프로세스의 상태**
- 프로세스가 컴퓨터 시스템의 리소스를 할당받는 양상에 따라 결정됨
- CPU 또는 메모리 할당 여부가 프로세스의 상태를 결정

### 프로세스 상태 변화 다이어그램

![lec5_process_state_diagram.png](/assets/images/lec5_process_state_diagram.png)

**Created State(생성 상태)**
- 작업(Job)에 관한 정보가 커널에 등록되면서 프로세스가 생성된 상태
- PCB가 커널 영역에 생성된 상태
- 프로세스 생성 시, 커널에서는 사용 가능한 잔여 메모리 공간이 충분한지에 따라 다음 상태를 결정
  - 메모리 공간이 충분 -> Ready State
  - 메모리 공간 부족 -> Suspended Ready State

**Ready State(준비 상태)**
- 프로세스가 CPU를 제외한 모든 리소스를 할당받아 대기 중인 상태
- 대기 중인 프로세스를 저장하기 위해 Queue 자료구조를 사용
- 이 상태의 프로세스는 CPU가 할당되는 즉시 실행 가능
- dispatch(= schedule): 프로세스에 CPU를 할당하는 것(준비상태 -> 실행 상태)

**Running State(실행 상태)**
- 프로세스가 시스템상의 모든 리소스를 할당받아서 실제 작업을 수행하고 있는 상태
- 이 상태의 프로세스는 다음의 상황에서 실행이 중단될 수 있음
- preemption(= timer run out)
  - 프로세스의 작업이 완료되기 전에 할당받은 리소스 사용 시간이 만료되는 것
  - 실행 상태 -> 준비 상태
- block/sleep
  - 실행 도중 입출력이나 이벤트의 발생으로 인해 기존 프로세스가 할당받은 CPU의 사용이 막히는 것
  - 실행 상태 -> 중단 상태

**Blocked/Asleep State(중단/대기 상태)**
- 발생한 시스템 콜 및 이벤트의 처리가 완료될 때까지 기다리는 상태
- 시스템 콜/이벤트의 CPU 사용 우선순위가 높기 때문에, CPU를 할당할 대상이 변경되어 기존 프로세스의 작업이 중단됨
- 리소스마다 프로세스 대기열을 형성 -> 리소스마다 Queue 자료구조 사용
- wakeup
  - 시스템 콜/이벤트의 처리가 완료되어 중단되었던 프로세스의 작업을 재개하는 것
  - 중단 상태 -> 준비 상태
  - 대기열 순서를 유지하기 위해, 중단상태에서 실행상태로 넘어가지 않고 준비상태로 전환

**Suspended State(지연된 상태)**
- 프로세스가 메모리를 할당받지 못한 상태
 - Suspended Ready State(지연된 준비 상태) : 생성된 프로세스가 곧바로 메모리를 할당받지 못한 준비 상태
 - Suspended Blocked State(지연된 중단 상태) : 프로세스가 메모리를 할당받지 못한 중단 상태
- 프로세스가 메모리를 할당받지 못하거나 빼앗기면, 현재까지의 메모리 상태를 swap device에 저장(= swap-out)

**Terminated/Zombie State**
- 실행 중이던 프로세스가 종료된 상태
- 프로세스는 그동안 할당받았던 모든 리소스를 반납하고, 커널 영역의 PCB는 삭제됨
  - 필요에 따라, 일부 PCB 정보를 커널에 남겨두기도 함(-> Zombie State)

## 4. 인터럽트
### 인터럽트의 정의
- 현재 프로세스의 외부에서 발생한, 예상치 못한 이벤트
- 시스템 콜, 자원 할당 시간 만료, 표준 입출력, 프로그램/하드웨어에서의 오류 등에 의해 발생

### 인터럽트 처리 절차
1. 인터럽트 발생
2. 기존의 프로세스 중단
  - 커널이 개입하여 기존의 프로세스는 중단됨
  - 프로세스가 중단될 때 CPU 레지스터에 저장된 데이터에 관한   상태를 PCB에 저장(context saving)
3. 인터럽트 발생 지점 및 발생 원인 파악
  - 커널 영역의 인터럽트 핸들러에서 인터럽트가 발생한 지점과 전달된 인터럽트 신호를 확인
4. 인터럽트 서비스 수행 여부를 결정
  - 발생한 인터럽트의 중요도/심각성에 따라 인터럽트 처리 여부가 결정됨
5. 인터럽트 서비스 루틴 실행
  - 3.의 인터럽트 신호에 매핑되는 인터럽트 서비스 루틴을 실행
  - 인터럽트 처리 완료 시, 중단된 프로세스는 실행 상태나 준비 상태로 전환됨

## 5. 컨텍스트 스위칭

### 관련 용어 정리
**Context(문맥)**
- 프로세스의 실행과 관련된 정보들의 집합
- CPU의 레지스터, 메모리의 Code, Data, Stack 영역 및 PCB에 저장된 데이터에 해당

**Context Saving(문맥 저장)**
- 현재 프로세스가 중단될 때, CPU 레지스터에 저장된 데이터를 해당 프로세스의 PCB에 백업하는 작업

**Context Restoring(문맥 복원)**
- 중단된 프로세스의 작업을 재개하기 위해, PCB에 백업된 CPU 레지스터의 데이터를 불러오는 작업

**Context Switching(문맥 교환)**
- 실행 중인 프로세스를 다른 프로세스로 전환하는 작업
- 현재 프로세스의 실행 정보를 PCB에 저장하고, 다음에 실행할 프로세스의 실행 정보를 복구하는 작업

### 컨텍스트 스위칭과 운영체제의 성능
- 컨텍스트 스위칭이 자주 발생하면 운영체제의 성능이 낮아짐
  - 프로세스 실행 정보를 PCB에 저장하거나, PCB에 백업한 정보를 시스템으로 불러오는 과정에서 비용 발생
  - 이러한 비용은 컨텍스트 스위칭이 다층적으로 발생할수록 누적(재귀 호출과 유사)
- 불필요한 컨텍스트 스위칭을 줄이기 위해 스레드가 사용됨
