# [디자인 패턴] 의존성 뒤집기 원칙

### 순 공부 시간 : 25.9.7.(일) 1118 ~ 1220 (62분), 1420 ~ 1457(37분)

### 학습 목표 : 의존성 주입 개념 이해하기

### 학습 내용 요약 :

- DIP (Dependecy Inversion Principle)
- 치즈 피자, 야채 피자, 시카고 피자 등의 구상 클래스를 직접 생성하고, 사용하지 말고, 피자라는 인터페이스 혹은 추상 클래스를 만들어서 그 인터페이스 혹은 추상 클래스에 의존하게 하자

## 의존성 주입

- 의존성 : A가 B에 의존한다는 것은 B의 변경사항에 따라 A 또한 변해야 한다는 것을 의미함
- 의존성 주입은 **제어의 역전(Inversion of Control, IoC)** 원칙을 따름. 여기서 '제어'는 객체의 생성 및 관리에 대한 제어를 의미합니다.
- (주입전) 메인 모듈이 ‘직접’ 다른 하위 모듈에 대한 의존성을 주기
  - 메인모듈 → 여러 하위 모듈 (메인 모듈에서 여러 하위 모듈들을 직접 생성하고, 사용한다)
- (주입후) 중간에 의존성 주입자(dependency injector 혹은 DI container) 가 직접 의존하는 것을 가로채 메인 모듈이 간접적으로 의존성을 주입하는 방식. 즉, 메인 모듈이 더이상 하위 모듈을 직접 생성하지 않음. DI 컨테이너가 직접 하위 모듈들을 대신 생성하고, 메인 모듈이 필요로할 때 주입해줌
  - 메인 모듈 → 의존성 주입자 (인터페이스 혹은 추상 클래스) ← 여러 하위 모듈
  - **`메인 모듈(Client)` → `인터페이스(Interface)`**
    - 메인 모듈은 `Interface`가 제공하는 기능을 사용하므로 `Interface`에 **의존**합니다.
    - UML에서는 점선 화살표(`-->`)로 표현하며, **"의존성(Dependency)"** 관계를 나타냅니다.
  - **`하위 모듈(Service)` --|> `인터페이스(Interface)`**
    - 하위 모듈은 `Interface`의 기능을 **구현**하므로 `Interface`에 **의존**합니다.
    - UML에서는 점선에 속이 빈 삼각형 머리를 가진 화살표(`-|>`)로 표현하며, **"구현(Realization)"** 관계를 나타냅니다.
- 장점 : 하위 모듈들을 쉽게 교체할 수 있는 구조가 되어 테스팅하기 쉽고 마이그레이션하기도 수월함.
  - 구현할 때 추상화 레이어를 넣고 이를 기반으로 구현체를 넣어 주기 때문에 애플리케이션 의존성 방향이 일관되고, 애플리케이션을 쉽게 추론할 수 있으며, 모듈 간의 관계들이 좀 더 명확해짐
- 단점 : 모듈들이 더욱더 분리되므로 클래스 수가 늘어나 복잡성이 증가될 수 있으며 약간의 런타임 페널티가 생길 수 있음
- 원칙 : 상위 모듈은 하위 모듈에서 어떠한 것도 가져오지 않아야 합니다. 둘 다 추상화에 의존해야 하며, 이때 추상화는 세부 사항에 의존하지 말아야 합니다.

**주입 전 (직접 의존) : 메인 모듈(사용자 서비스)은 하위 모듈(이메일보내기)에 직접 의존한다.**

이 코드는 알림 기능(`NotificationSender`)을 사용하는 메인 모듈(`UserService`)이 **직접** 하위 모듈(`EmailSender`)을 생성하고 의존하는 방식입니다. `UserService`가 `EmailSender`에 직접적으로 연결되어 있어, 만약 SMS 알림으로 변경하려면 `UserService` 코드를 직접 수정해야 하는 문제가 발생합니다.

```java
// 하위 모듈: 이메일 전송 기능
class EmailSender {
    public void sendEmail(String to, String message) {
        System.out.println("이메일로 메시지 전송: " + to + " - " + message);
    }
}

// 메인 모듈: 사용자 서비스 (직접 의존)
class UserService {
    // UserService가 EmailSender에 직접 의존
    private EmailSender emailSender;

    public UserService() {
        this.emailSender = new EmailSender(); // 직접 객체 생성
    }

    public void notifyUser(String userId, String message) {
        // 실제 알림 로직 -> EmailSender 의 메소드 사용
        String userEmail = getUserEmail(userId); 
        emailSender.sendEmail(userEmail, message);
    }

    private String getUserEmail(String userId) {
        // 유저 ID로부터 이메일을 찾는 로직 (생략)
        return userId + "@example.com";
    }
}

// 실행 클래스
public class MainBeforeDI {
    public static void main(String[] args) {
        UserService userService = new UserService();
        userService.notifyUser("user123", "안녕하세요! 계정이 생성되었습니다.");
    }
}
```

---

**주입 후 (간접 의존)**

**이 코드는 **추상화(인터페이스)**를 도입하고 의존성 주입을 적용**한 방식입니다. `UserService`는 이제 구체적인 `EmailSender`나 `SmsSender`가 아닌 `NotificationSender`라는 **인터페이스**에만 의존합니다. 메인 클래스(`MainAfterDI`)가 **의존성 주입자** 역할을 하여, 어떤 구현체를 사용할지 결정하고 `UserService`에 주입해줍니다.

이 구조는 알림 방식을 변경할 때 `UserService` 코드를 수정할 필요 없이, 주입하는 객체만 `EmailSender`에서 `SmsSender`로 바꾸면 되므로 훨씬 유연합니다.

```java
// 추상화 레이어: 인터페이스
interface NotificationSender {
    void send(String to, String message);
}

// 하위 모듈 1: 이메일 전송 (구현체)
class EmailSender implements NotificationSender {
    @Override
    public void send(String to, String message) {
        System.out.println("이메일로 메시지 전송: " + to + " - " + message);
    }
}

// 하위 모듈 2: SMS 전송 (구현체)
class SmsSender implements NotificationSender {
    @Override
    public void send(String to, String message) {
        System.out.println("SMS로 메시지 전송: " + to + " - " + message);
    }
}

// 메인 모듈: 사용자 서비스 (간접 의존)
class UserService {
    // 추상화에만 의존 : UserService -> NotificationSender <- Email / SNS Sender
    private NotificationSender sender;

    // 생성자를 통해 의존성 주입
    public UserService(NotificationSender sender) {
        this.sender = sender;
    }

    public void notifyUser(String userId, String message) {
        String userInfo = getUserInfo(userId);
        sender.send(userInfo, message); // 인터페이스의 send 메서드 호출
    }

    private String getUserInfo(String userId) {
        // 유저 정보(전화번호 등)를 찾는 로직 (생략)
        return userId + "-phone-number";
    }
}

// 실행 클래스: 의존성 주입자 역할
public class MainAfterDI {
    public static void main(String[] args) {
        // 이메일 전송 구현체를 주입
        System.out.println("--- 이메일로 알림 ---");
        NotificationSender emailSender = new EmailSender();
        UserService emailUserService = new UserService(emailSender);
        emailUserService.notifyUser("user123", "안녕하세요! 계정이 생성되었습니다.");

        System.out.println("\n--- SMS로 알림 ---");
        // SMS 전송 구현체를 주입
        NotificationSender smsSender = new SmsSender();
        UserService smsUserService = new UserService(smsSender);
        smsUserService.notifyUser("user123", "안녕하세요! 계정이 생성되었습니다.");
    }
}
```
