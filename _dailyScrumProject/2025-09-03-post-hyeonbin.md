## 1. 다중 프로그래밍(Multi-Programming)

- 시스템 내부에 여러 개의 프로세스가 존재하는 것을 의미
- CPU는 1개뿐 -> 스케줄링을 통해 리소스를 할당할 프로세스를 선택하는 작업이 요구됨
- 다음의 방식으로 리소스를 할당
  - **시간 분할(time sharing)**
    - 1개의 리소스(주로 CPU)를 여러 프로세스/스레드가 번갈아 가면서 사용
    - 예) 프로세스 스케줄링 -> CPU 사용 시간을 여러 프로세스에게 분배
  - **공간 분할(space sharing)**
    - 1개의 자원을 여러 개로 분할 -> 여러 프로세스가 동시에 사용
    - 예) 프로세스의 작업을 수행하기 위한 메모리의 할당

## 2. 스케줄링의 목적
- 응답시간, 작업 처리량, 자원 활용도를 개선함으로써 시스템의 성능을 향상시키는 것

### 시스템의 성능 지표
**개요**
- 시스템 사용 목적에 따라 각 지표별 중요도가 달라질 수 있음
- 일반적으로 시스템의 성능을 향상시킨다는 것은 아래의 지표들을 개선한다는 의미와 동일

**시스템의 주요 성능 지표**
- 응답시간(response time)
  - 작업을 요청받은 시점부터 응답을 받을 때까지의 시간
  - 대화형 시스템, 실시간 시스템에서 중요
- 작업 처리량(throughput)
  - 단위 시간동안 완료된 작업의 수
  - 일괄 처리 시스템에서 중요
- 자원 활용도(resource utilization)
  - 주어진 시간 동안 자원이 활용된 시간
  - 고비용의 리소스를 사용할 때 중요

**그 외의 시스템 성능 지표들**
- 공평성(fairness)
  - 리소스의 균등한 할당을 보장하는 것을 의미
  - 특정 프로세스의 우선순위가 계속 밀리거나, 데드락 발생으로 인해 실행 대기 상태에 빠지는 것을 방지
- 예측 가능성
  - 적정 시간 내에 응답을 보장하는 것을 의미

### 용어 정리
**대기 시간(waiting time)**
- 대기 큐에 도착한 프로세스가 리소스를 할당받아 작업을 시작할 때까지 걸리는 시간

**실행 시간(burst time)**
- 프로세스의 실행이 시작될 때부터 종료될 때까지의 시간

**응답 시간(response time)**
- 대기 큐에 도착한 프로세스가 리소스를 할당받아 작업을 수행하던 중 최초로 응답을 수신할 때까지 걸리는 시간

**반환 시간(turn-around time)**
- 프로세스가 대기 큐에 도착할 때부터 실행을 완료할 때까지 걸리는 시간
- 대기시간 + 실행시간

## 3. 스케줄링의 기준

### 개요
- 스케줄링 기법을 선택할 때 고려하게 되는 항목들을 의미

### 주요 스케줄링 기준

**프로세스의 특성**
- 프로세스 실행 시, CPU 사용 -> 입출력 대기의 흐름이 반복됨
  - CPU 사용 시간과 I/O 대기시간 중 어느 것의 비중이 더 높은지에 따라 스케줄링에서의 순위를 결정
  - CPU 이용 비중이 높으면 Compute-Bounded
  - 입출력의 비중이 높으면 I/O-Bounded

**시스템의 특성**
- 시스템의 종류에 따라, 해당 시스템에서 중시되는 성능 지표가 달라질 수 있음
  - 일괄 처리 시스템: 단위 시간 동안의 처리량을 중시
  - 대화형/실시간 시스템: 응답 시간을 중시

**프로세스의 긴급성, 우선순위**
- 프로세스의 중요성과 시급성이 높을수록 스케줄링에서의 우선순위가 높음

## 4. 스케줄링의 단계
### 개요
- 발생 빈도 및 할당되는 리소스에 따라 스케줄링의 단계를 구분

### 장기 스케줄링(Long-term Scheduling)

- 시스템 커널에 등록할 작업(Job)을 결정하는 **Job Scheduling**을 의미
- 다중프로그래밍 정도를 조절하는 것이 목적
  - 하나의 컴퓨터 시스템에서 동시에 실행 가능한 프로세스의 개수를 조절
  - I/O Bounded와 Compute-Bounded의 비중이 비슷해야 데이터 탐색 시 시스템 효율이 증대됨
- 시분할 시스템에서는 상대적으로 중요도가 낮음
  - 동시에 실행가능한 프로세스의 개수보다는 응답 속도가 더 중요하기 때문

### 중기 스케줄링(Mid-term Scheduling)

- 현재 대기 중인 프로세스들에게 메모리를 할당하기 위한 우선 순위를 부여

### 단기 스케줄링(Short-term Scheduling)

- 다음에 CPU를 할당할 프로세스를 결정하는 **Process Scheduling**을 의미
- 가장 빈번하게 발생하는 스케줄링
  - 인터럽트, I/O 블록, 시분할에 의한 리소스 사용 시간 만료 등이 주요 발생 원인
  - 시스템의 성능에 크게 영향을 끼치므로, 신속해야 함.

## 5. 스케줄링의 정책(Policy)

### 선점형 스케줄링(Preemptive Scheduling)
- 한 프로세스가 사용 중인 리소스를 다른 프로세스가 강제로 빼앗아 사용할 수 있음
- 컨텍스트 스위칭으로 인해 시스템의 성능이 다소 저하될 수 있음

### 비선점형 스케줄링(Non-preemptive scheduling)
- 프로세스가 할당받은 리소스는 해당 프로세스가 스스로 반납할 때까지 계속 사용
- 컨텍스트 스위칭으로 인한 성능 저하가 적음
- 프로세스 간 우전순위의 역전 평균적인 응답 시간이 증가

### 우선순위(Priority)

**개요**

- 스케줄링을 수행하기 위해, 각 프로세스마다 우선순위를 부여하는 방법

**정적 우선순위(static priority)**
- 프로세스 생성 시 부여된 우선순위는 프로세스가 종료될 때까지 유지
- 구현이 쉬우나, 시스템 환경 변화에 대응하기 어려움

**동적 우선순위(dynamic priority)**
- 프로세스의 상태 변화에 따라 프로세스에게 부여된 우선순위가 변동될 수 있음
- 우선순위를 다시 산정해야 하므로 구현이 복잡하나, 시스템 환경 변화에 유연하게 대응할 수 있음.
