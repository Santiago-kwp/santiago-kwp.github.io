### 학습 내용 요약 :

- 이벤트 카운터는 은행 창구의 띵동 하여 고객의 순번을 부르는 것으로 카운터는 정수형 변수로 증가만 하게되며, 카운터의 정수형 변수와 같은 번호를 가진 고객을 응대하게 된다.
- 시퀀서는 고객이 뽑는 번호표와 같은 역할을 하며, 마찬가지로 정수형 변수로 증가만 하게 되며, 이벤트 카운터가 고객이 뽑는 번호를 불러줄 때까지 대기하며, 이벤트 카운터와 같은 숫자가 되면 고객은 서비스를 받는다.
- 연산은 ticket(S) , await (E, v), advance(E) 세 가지로 나뉘며 각각
  - ticket(S) : 자신의 티켓 번호, v ← S를 받고, 티켓 번호를 하나 증가시킨다. (S = S + 1)
  - await(E, v) : 은행 창구의 E가 v 가 될 때까지 기다린다. if (E < v) 면 대기. E ≥ v 면 실행
  - advance(E) : 실행이 끝났다면 E = E +1 하고, 대기 중인 다음 사람을 부른다.
- 버퍼는 원형 대기 큐로 정의되며, 생산자의 경우는 원형 대기 큐에 공간이 하나 이상 있을 때까지 기다리는 연산을 수행하고 : await(Out, t-N + 1)
  - 현재 버퍼 안의 잔여 공간 : N (버퍼 크기) + Out(소비자가 소모한 물건 수) - t (현재 생산하러 온 생산자의 번호) ⇒ 현재 버퍼 안의 잔여 공간이 없다면 ( 공간 < 1), 기다린다.
- 소비자의 경우는 원형 대기 큐에 물건이 하나 이상 잇을 때까지 기다리는 연산을 수행한다. : await(In, u+1)
  - 현재 버퍼 안의 물건 수 : In ( 생산자가 생산한 물건 수) - u (현재 소비하러 온 소비자의 번호표) ⇒ 현재 버퍼 안의 물건이 없다면 (물건 수 < 1), 기다린다

### EventCount / Sequencer

- 은행의 번호표와 비슷한 개념
- Sequencer
  - 정수형 변수
  - 생성 시 0으로 초기화
  - 발생 사건들의 순서 유지
  - ticket() 연산으로만 접근 가능
- ticket(S)
  - 현재까지 ticket() 연산이 호출된 횟수를 반환
  - individual operation
- EventCount
  - 정수형 변수
  - 생성 시 0으로 초기화, 감소하지 않음
  - 특정 사건의 발생 횟수를 기록
  - read(E), advance(E), await(E, v) 연산으로만 접근 가능
- Read(E)
  - 현재 EventCount 값 반환 (현재 번호표가 몇 번인지 확인, 조회만)
- advance(E)
  - 은행원이 띵동 누르는 행위
  - E = E + 1
  - E 를 기다리고 있는 프로세스를 깨움 (wake-up)
- aWait(E, V)
  - V : 내가 들고 있는 번호표의 번호, E : 현재 은행원이 부르는 번호
  - if (E < V) 이면, 즉 내가 들고 있는 번호표의 번호가 은행원이 부르는 번호보다 크면 나는 기다려야 함 → E 에 연결된 Q_E 에 프로세스 전달(push) 및 CPU schedular 호출
- 아래의 그림과 같이, 처음에 프로세스가 도착하면 티켓팅을 하면서 v=0, s = 0 → 1 로 할당
  - 현재 E = 0, v = 0 이므로 임계영역에 진입
  - 다음 프로세스가 오면 티켓팅을 하면서 v = 1, s = 1 → 2로 할당되어, 임계 영역에 들어가지 못하고 대기실로 들어감. if ( E = 0 < v = 1) → 대기실 진입
  - 임계 영역에 진입했던 프로세스가 나오면서 advance(E)를 실행시키면 E = 1로 증가 시키고, 대기실에 있던 프로세스를 깨움 ⇒ 다음 프로세스가 임계 영역에 진입함

### Producer - Consumer Problem

- shared variable
  - Sequencer : Pticket(생산자 티켓), Cticket(소비자 티켓)
  - EventCount : IN : 물건을 놓는 이벤트, OUT : 물건을 꺼내는 이벤트
  - Array of message : 물건을 놓을 수 있는 공간인 buffer (크기 N)

생산자 입장

- 생산자가 도착하면 생산자 티켓을 끊고 ( t ← ticket(Pticket) ) 자기 순번이 올 때까지 기다린다 ( await(In, t) ), 먼저 물건을 놓을 수 있는지 확인해야 한다. ( await (Out, t - N + 1) )
  - In : 생산자의 현재 호출 번호, t : 현재 생산자 자신의 티켓 번호
  - Out : 소비자의 현재 호출 번호, 즉 현재까지 몇 명의 소비자가 소비했는지의 수량
  - await ( Out, t - N + 1) : Out < t - N + 1 이면 기다리겠다는 것으로,
    - N (버퍼 사이즈) < t - Out + 1 ⇒ 버퍼 사이즈보다 생산자가 생산한 량이 많아진다면 생산자는 기다리겠다. 언제까지? 버퍼에 공간이 남아있을 때까지
    - 현재 버퍼의 공간을 수식화 : N(아무것도 없을 때) - t(생산자가 공간을 t개만큼 예약함) + Out (소비자가 물건을 꺼내간 이벤트의 수) ⇒ 공간이 한 개 이상 있다 : N - t + Out ≥ 1 ⇒ 공간이 하나도 없다 ⇒ N - t + Out < 1 ⇒ 공간이 하나도 없다면 기다리겠다 : await ( Out, t - N + 1)
- 생산자가 버퍼에 공간이 남아서 생산할 수 있으면 버퍼에 하나를 채운다.
  - buffer[t mod N] = M
- 생산자가 나오면서 생산자를 생산자의 현재 호출 번호를 하나 증가 시키고 (In = In + 1), 기다리고 있는 생산자를 깨운다

소비자 입장

- 소비자가 도착하여 소비자 티켓을 끊고 u 라는 번호표를 받고, 현재 소비자 호출번호(Out) 가 u가 될때까지 기다린다 ( = await(Out, u) )
- 소비자의 대기가 끝나면 들어가기 전에 버퍼에 물건이 있는지 확인해야 하므로 await (In, u + 1) 을 통해서 In : 생산자의 현재 호출 번호 ⇒ if ( In < u + 1) 까지 기다린다 ⇒ 즉, 생산자 수가 현재까지의 소비자 수보다 많을 때 까지 기다린다 ⇒ 버퍼에 물건이 1개 이상 있을 때 까지 기다린다.
- 버퍼에 물건이 있으면 내가 소비할 물건을 하나 가져와 m 에 저장하고 ( m = buffer[ u mod N ]; )
- 임계 영역에서 나오면서 advance(Out) 을 통해 소비자 호출 번호를 하나 늘리고 (Out = Out + 1), 기다리고 있는 소비자를 호출한 뒤
- 저장한 물건을 소비한다 = Consume the message m;
