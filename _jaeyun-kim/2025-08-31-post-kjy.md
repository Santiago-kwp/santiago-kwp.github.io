#### 작업(Job)
-설계한 프로그램과 프로그램이 처리하는 데이터를 묶어놓은 것
-시스템의 실행 요청 전의 상태
-간단하게 프로그램이라고도 함

#### 프로세스
-잡이 시스템에 등록된 상태
-커널에 의해 관리됨
-프로세스 관리 블럭(PCB)를 할당받은 개체
-능동적인 개체

#### 프로세스 구분
역할 - 시스템/사용자
병행 수행 방법 - 독립/협력

#### 자원(Resource)의 개념
-커널의 관리하에 프로세스에 할당 또는 반납되는 수동적인 개체
-H/W 와 S/W로 분리

#### 프로세스 관리 블럭(PCB)
-프로세스를 관리하기 위해 모아둔 정보 저장 공간

#### PCB가 관리하는 정보
-PID
-스케줄링 정보
-프로세스 상태
-메모리 관리 정보
-입출력 상태 정보
-문맥 저장 영역
-계정 정보

------------------------------------------------
### 프로세스의 상태
#### Created State
-작업을 커널에 등록
-PCB할당 및 프로세스 생성

#### Ready State
-프로세서(CPU) 외에 다른 모든 자원을 할당 받은 상태

#### Running State
-실제로 실행하는 상황

#### Blocked/Asleep State
-프로세서 외에 다른 자원을 기다리는 상태

#### Suspended State
-메모리를 할당 받지 못한 상태
-메모리를 swap device에 보관

#### Terminated/Zombie State
-프로세스 수행이 끝난 상태
-모든 자원 반납

-----------------------------------------------

#### 인터럽트(Interrupt)
-예상치 못한, 외부에서 발생한 이벤트

#### Context Switching
-Context
프로세스와 관련된 정보들의 집합
-Context Saving
현재 프로세스의 Register context를 저장하는 작업
-Context restoring
Register context를 프로세스로 복구하는 작업
-----------------------------------------

### 스레드(Thread)
-같은 프로세스의 스레드들은 동일한 주소 공유
-Light Weight Process(LWP)
자원은 공유하고 제어만 가지므로 일반 프로세스보다 가벼움
-프로세서 활용의 기본 단위
-구성요소
Thread ID, Register set, Stack

#### 스레드의 장점
-사용자의 응답성
-자원 공유
커널의 개입을 피해 효율성 증가
-경제성
-멀티 프로세서 활용
병렬처리를 통해 성능 향상

#### 사용자 수준 스레드
-사용자 영역의 스레드 라이브러리로 구현됨
-커널은 스레드의 존재를 모름
커널의 관리를 받지 않음
-다대일모델

#### 커널 수준 스레드
-커널이 직접 관리
-부하가 큼
-커널이 각 스레드를 개별적으로 관리
프로세스 내 병행 수행 가능
-일대일모델

#### 혼합형 스레드
-다대다 모델
-효율적이면서도 유연함
